# 统一电商前端架构

## 范围与事实

S10a交付同一SPA内的运营管理台和会员消费端，使用已完成S4–S9真实HTTP契约。现有平台没有前端；参考仓营销台使用React，权益台使用AntDesign，不搬入旧仓业务或改旧规则迁移门禁。外部IdP由用户明确后置，当前凭据入口只接受运维签发的不透明访问令牌；不伪造第三方登录。

## 技术与边界

React19.3.0、TypeScript7.0.2、Vite8.3.0、AntDesign6.6.5。Node24.12.0满足Vite官方20.19+/22.12+约束；Ant6官方支持React18+且不需React19兼容补丁。版本锁定package-lock.json，新增依赖检查MIT/Apache许可及npm audit。官方资料：https://vite.dev/guide/ 、https://react.dev/versions 、https://ant.design/docs/react/migration-v6/ 。不引入SSR/RSC、微前端或第二组件库。Material未选因现有B端表单经验为Ant；Tailwind未选以免另造Table/Form系统。

一个应用、两个角色壳层、一套Ant ConfigProvider主题配置。app负责认证/URL路由；shared包含类型化HTTP、DTO和反馈原语；features按会员购物、订单、营销、运营页面等作业组织。Hash路由避免Java端添加任意SPA回退，store选择进入hash查询参数。构建产物由Spring静态资源托管，同源API；开发Vite代理仅到本机后端。

## 信息架构

- 未登录：凭据输入、角色识别、错误恢复；令牌只存会话内存，刷新重新输入，退出清空购物车和数据。
- ADMIN：经营总览（首页真实域聚合）、订单工作台、主数据（会员/商家/店铺/商品/库存）、营销（活动/人群/规则/预算）、权益（券定义/权益定义/钱包补偿）、旅程（节点编辑/版本审批/实例控制）、运营页面（组件与动作配置/真实预览/发布/回退）、履约售后（发货/收货/审批/退货/退款）、事件运维（隔离重放）。
- MEMBER：店铺商品浏览→购物袋→服务端报价→地址与确认下单→订单/支付查询与取消→售后申请；券中心/钱包、内部权益核销、站内信。
- 不存在真实渠道授权时，沙箱管理操作明确标注“本地沙箱”，不会让会员看到“真实支付成功”按钮。

## 状态、契约和一致性

服务端金额字符串直接展示；前端数量只影响报价输入，不自行宣布应付、优惠或库存结果。购物袋为会话临时态；报价在商品/券变化时失效，提交订单使用quoteId。URL只保存路线/店铺，不保存令牌和地址。GET请求可取消，切页或身份切换不能回填旧数据；操作禁用重复点击，失败重试保留相同幂等键，修改输入才新建键。状态冲突提示刷新；网络未知不当作业务失败或成功。

表单使用已知DTO，不把数据库实体或任意JSON注入业务请求。规则编辑器生成有限Compare/All/Any/Not；旅程编辑器生成已支持的WAIT/DECIDE/GRANT/NOTIFY/END；低代码只渲染已冻结数据源与动作。JSON仅在高级审阅区展示，不作为唯一产品操作界面。

列表有界游标分页；不能把当前页计数称为全平台指标。所有业务数组由API加载，无硬编码订单/商品/活动。错误保持真实401/403/409/5xx和traceId；空态与服务不可达明确不同。重要异步状态显示“已受理/处理中/结果待确认”，手动刷新或有界轮询，不伪造即时完成。

## 视觉与设备

### 2026-09-27 前端视觉改版（S-VR-01）

本轮根据用户要求应用更新后的前端架构 Skill。原固定蓝灰色板、饱和状态及 32px 控件是历史默认，没有用户对具体样稿的认可记录；本轮在既有 React/Ant/API/路由边界内更新这些视觉假设。用户确认的是“简洁企业工作台＋重图片展示”的方向；下面具体 token、尺寸和布局是设计 Owner 的可调整决策，未宣称用户看过并认可页面。需求和实施边界见 [BRIEF](../frontend-visual-refresh/BRIEF.md) 与 [切片](../frontend-visual-refresh/IMPLEMENTATION_SLICES.md)。

theme.ts 中同一份 Ant ConfigProvider 主题配置是公共主题权威。沿用蓝色识别，画布更轻、边界更柔、语义标签采用深字浅底；工作台按任务分层，商城采用图片与内容节奏。不同页面构图和角色圆角不是第二套系统，不引入新库、字体服务或图片服务。

|---|---|

角色/路由与既有业务流程不变。经营总览先做代表页面：真实汇总、成交趋势、会员/商品状态、辅助入口和统计口径构成清晰层级；后续列表/详情/表单使用相同主题。不存在新 API 时不增加待办数字、增长率、营销效果或优惠承诺。

商城不是新官网：保留店铺切换、真实类目/搜索、商品目录、详情、购物袋与结算；图片只取商品接口 images 与项目已有合法素材。原 coffee.svg 是包装示意图，继续保留接口 alt，不冒充真实摄影或真实产品截图。没有图片时给可理解占位，不用商品首字制造伪图片。服务说明使用用户能理解的购物/优惠/订单/售后表达，不把内部实现细节放入产品流程。

设备范围沿用：1440/1280 运营桌面、390 既有窄屏与会员手机；管理宽表只在自身容器滚动。加载、空、403/401、409、5xx/网络未知、提交忙碌与 202 语义继续来自现有组件/契约，纯视觉改版不重设状态规则。

本轮无外部网站截图输入，以当前浏览器基线与用户方向为设计输入，已查看参考与取舍在 IMPLEMENTATION_EVIDENCE 中记录。当前版本实际截图必须绑定 route、视口、状态、源码摘要、时间与查看观察；当前取图后实际查看与回归通过才推进 DONE。用户反馈与模型自审分开记录，不把改后截图自动登记为用户批准的回归基线。
