# 风险与待决事项

| ID | 风险/未知 | 当前控制 | 生效阶段 |
|---|---|---|---|
| R1 | 不同旧系统身份、租户、组织、店铺 ID 并非天然相同 | 上游适配显式映射；当前只处理调用方提供的同域值，不执行鉴权 | HTTP/数据接入前 |
| R2 | Spring Boot 3/4、Jackson 2/3、规则引擎依赖混用 | 首批无生产外部依赖；装配前官方版本兼容/维护/漏洞检查 | S4 |
| R3 | 旧规则迁移门禁未通过 | 新建条件树不迁移旧实现；旧计划保持 BLOCKED | 任何旧代码/数据迁移前 |
| R4 | 渠道支付/发奖副作用不可逆 | 当前无渠道调用；真实接入需要沙箱、商户及可信验签/查单契约 | S6–S8 |
| R5 | 纯状态机不证明数据库并发安全 | 明确未实现 CAS/事务/Inbox；DB集成失败不能放行 | S4–S7 |
| R6 | 人群事实可陈旧/不可信 | 内核只做三值判断；上游应绑定来源/主体/有效期，尚未接线 | S4/S8 |
| R7 | 单商家单店/CNY/单活动只是首阶段假设 | 首批显式限制，不自动扩为跨店叠加支付模型 | 扩交易模式前 |
| R8 | 原仓 dirty，整体复制可能夹带用户修改与秘密 | 只读抽样，保留源码指纹，不复制配置和业务库 | 全过程 |
| R9 | 新项目 Git 配置在任务期间出现 | 收尾重读 Git 状态；复用 origin，正常推送，保护任何远程现有历史 | Git 交付 |
| R10 | 没有峰值/延迟/恢复/保留指标 | 不编造 SLA，输入上限不等于容量验收；在真实压测和恢复目标确定后验证 | 本地闭环后、上线前 |

下一执行视野需要冻结的具体业务语义：一租户是否可有多商家、店铺归属权威；首个会员 subject 映射；金额/运费/税与零元订单政策；券预占及退款权益恢复政策。没有这些答案仍可建设隔离数据库基础和主数据，但不能接真实支付或覆盖旧业务行为。
