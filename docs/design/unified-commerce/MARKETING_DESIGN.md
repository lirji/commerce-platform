# 营销领域建设方案

本文件描述目标行为；实际已实现范围只有 CONTRACTS C1–C3。其余是后续切片，不因文件存在宣称已交付。

## 运营到交易的版本链

运营创建活动草稿，选择渠道/店铺/商品/有效期，绑定人群版本、规则版本、权益定义及优惠方案，先校验再预览，审批通过后发布不可变 Release。草稿可修改；已发布版本不得原位改条件。暂停影响新决策，已确认订单和履约按原快照与明确补偿政策处理。回滚是激活旧的可用版本，不抹去已经产生的权益与资金事实。

活动生命周期：DRAFT → IN_REVIEW → APPROVED → PUBLISHED → PAUSED/ENDED；被驳回回到新草稿，已发布修改产生新版本。发布应用必须一次切换完整 Release 引用，不能规则已更新、人群仍旧、权益 SKU 不存在。发布校验包含依赖版本、主体/店铺权限、输入上限、有效期、权益可用与预算；验证成功不代表真实渠道发奖成功。

## 子能力与边界

| 子能力 | 持久化权威及规则 | 首批复用方向 |
|---|---|---|
| 人群 | 定义、快照、主体命中和 watermark；来源不新鲜则未知，不能默认全员 | 参考营销 AudienceMembershipProjection；先批量/明确快照，流式实时画像后置 |
| 动态规则 | 字段目录、类型、受限 AST、规则版本、解释记录；编译与发布分离 | 已实现受限条件树内核；Drools/DMN 适配待专门评估 |
| 权益 | 定义/SKU/额度、资格、预占、受理、发放、冲正与账本 | 参考 benefit-center；发放成功来自渠道可信事实及本地账本 |
| 优惠 | 满减/折扣/券/包邮、叠加组、互斥、限额、预算、资方、行分摊 | 已实现整单单活动固定减免择优；叠加和分摊给资方需另定契约 |
| 旅程 | 定义版本、实例、节点状态、timer、效果命令、检查点 | 参考 JourneyApplicationService；实例绑定版本，节点完成和输出任务同事务 |
| 低代码 | 组件/字段 schema、页面/活动编排 DSL、校验器、预览、审批与发布 | 复用现有 console 的交互经验；新页面走真实 API，数据库种子提供演示数据 |
| 测量 | 曝光、参与、下单、支付、发放、退款的事件投影 | 只读分析数据；不能根据统计投影直接执行资金/权益决策 |

## 复杂交易场景

- 优惠并发抢占：资格只是建议；预算、券和次数在权威数据库原子预占。唯一键与有条件更新防重复领取；报价过期或关单释放，未决支付不能抢先释放。
- 支付后权益：OrderPaid 的消费幂等键绑定订单和权益版本；受理、渠道处理中、成功、失败、待人工分开。超时不能生成第二笔渠道请求，先查单/对账。
- 部分退货：以订单固化的行金额与优惠分摊为基础，累计退款不能超过实收；券返还、运费与已消费权益补偿是显式政策，不能重算当下活动。
- 跨店购物：交易组负责统一展示，各子订单绑定各自商家/店铺与收款主体。合并支付、拆单优惠与分账需要正式业务决策，首个单店闭环不预先假装支持。
- 旅程重试/取消：输入事件去重，迟到/乱序不回退状态；取消阻止新任务，不能声称撤销已发送通知/已发放权益；租约与版本阻止旧执行器再次写入。

## 验收顺序

先“活动版本+可信人群→优惠报价→订单快照”，再“额度/券预占→支付确认→权益履约”，然后“售后补偿→旅程→低代码运营”。每步覆盖重复、并发、渠道未知、超时恢复与重启，不以页面能打开或 Broker 已发送代替业务验收。
