# 营销领域实现

当前已实现 S1、S8、S9、S10，精确 DTO、状态和验收约束分别见总 CONTRACTS、s8/CONTRACTS、s9/CONTRACTS、s10/CONTRACTS。本文件概括现有行为，不取代版本契约。

## 决策与版本

marketing 纯领域内核计算类型化受限 AST，可信事实来自服务端会员、人群快照、订单等来源。缺失、过期或类型不符为 UNKNOWN，NOT UNKNOWN 仍 UNKNOWN。规则不执行任意脚本，不访问网络/数据库。活动、人群和规则使用显式版本，报价保存优惠和来源快照。增强活动走 DRAFT → IN_REVIEW → APPROVED → PUBLISHED，可暂停；S4 无增强 policy 的简版发布保持旧契约兼容。

优惠支持固定减免和比例折扣/封顶，一次选择一个活动，可按显式策略叠加一张券。预算、券及权益资格在下单事务内预占；报价命中不等于额度承诺。平台/商家资方和 SKU 行分摊守恒，售后按原订单快照累计退款，不重新套用最新活动。营销预算支付后转支出，退款不自动恢复预算。

## 券与权益

券定义有店铺、有效期、库存配额、门槛及叠加策略，同一会员/定义版本只领取一次。AVAILABLE → HELD → USED；取消按可信未收款事实释放，全额退款且券仍有效时返还，旧占用不能释放新订单占用。

内部权益为非现金体验额度，定义有总配额、单位和有效期。下单预占，支付事实通过 Outbox/Inbox 发放；消费采用台账和条件更新防负数。全退撤销未使用权益；已使用形成 COMPENSATION_REQUIRED，由管理员确认追回或核销后闭合，不能假装回滚消费历史。ORDER/JOURNEY 来源分别持久化，避免通知重试重复发放。

## 旅程与低代码

旅程定义最多 32 节点，必须无环且全部可达；WAIT、DECIDE、GRANT、NOTIFY、END 节点不接受任意程序。定义审批后发布不可变版本，支持管理员报名及订单支付触发。实例持久化输入版本、当前节点、到期/截止时间、尝试次数和检查点；节点效果与推进同事务，失败有限退避后隔离。取消仅阻止未来节点，无法撤销已发通知；全退先取消关联旅程再冲正权益，迟到支付事件不能重新报名。

低代码为受治理的固定 DSL：最多 8 个数据区块、4 个白名单动作。数据源为活动、旅程、预算、券和权益；预览只读真实 API 数据，不保存页面或执行动作。版本审批发布、暂停和恢复旧版本不撤销业务操作。动作 CREATE_CAMPAIGN、CREATE_COUPON、ENROLL_JOURNEY 复用对应领域的授权、幂等和审计，不能拼任意 URL/SQL/脚本。

管理台提供活动规则编辑、旅程节点编辑、页面构建/预览/发布以及交易运营；会员端提供商品、订单、券、权益与通知。数据均经真实 API，演示数据持久化到隔离 MySQL。

## 明确边界

当前交易为单店 CNY，不包含跨店拆合单/合并收款/分账、多币种、税费引擎、任意促销组合、外部短信触达、实时画像流计算或通用拖拽应用开发平台。真实渠道联调后置，通知目前为数据库站内信。生产营销分析和容量目标未以演示验收冒充实现。
