# 统一电商建设简报

日期：2026-09-23。模式：REFERENCE_SYSTEM → 新建 commerce-platform。用户已明确选择按新建设任务推进，参考并逐步复用现有仓库；旧规则迁移保持原门禁。旧记录归档在 ../../evidence/previous-workspace-progress.md。本任务不把旧 EVOLUTION-rules 的状态改为通过。

目标：基于 DDD 与模块化单体，覆盖会员、商家、店铺、商品、营销、交易、订单、支付、履约、售后。营销覆盖活动、人群、动态规则、权益、优惠、旅程、低代码运营。角色包括消费者、商家运营、平台运营、客服、财务。

主链路：运营发布活动版本 → 会员购物 → 可信商品/人群快照 → 规则决策和优惠报价 → 库存/权益预占 → 下单 → 支付事实确认 → 履约 → 售后及资金/权益补偿。规则命中不等于授权，不等于权益发放成功；订单取消也不等于渠道未收款。

本次先给出全景方案，并开始首个工程里程碑：有界动态规则、可解释优惠报价、订单生命周期领域内核及真实构建验证。它是后续 API/持久化闭环的前置交付，不能称作完整电商 MVP。原仓只读；不迁移存量数据、不修改共享数据库、不调用真实支付/发奖、不部署。

暂定约束：首个交易闭环为同租户、单商家单店、CNY 两位小数、整数件数、最多 100 行。跨店购物车后续拆交易组和子订单，不能简单移除店铺校验。首个优惠采用单活动择优固定减免，活动可配金额门槛与受限条件树；叠加、百分比、券占用与资金分摊后续单独定义。

规模、SLA、RTO/RPO、真实渠道、退款/运费/税务规则均未提供，不编造承诺。首个内核的输入上限用于资源边界，不是生产容量结论。正式接入前须确认商家/租户关系、主身份映射、支付收款主体、权益和售后政策。
