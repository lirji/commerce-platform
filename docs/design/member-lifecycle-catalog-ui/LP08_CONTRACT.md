# LP08 生命周期旅程及效果比较契约

沿用现有旅程审批、不可变版本、节点检查点、有限重试、实例取消、UTC及ADMIN权限。不新增中间件。

## 生命周期

Definition追加可空lifecycle `{thresholdDays,cartDelaySeconds,scanIntervalSeconds,conversionWindowDays}`，旧构造和JSON兼容。新增触发BIRTHDAY/DORMANT/REPURCHASE/CART_ABANDONED；必须有controls及lifecycle。阈值1–365天，加购等待60–604800秒，扫描间隔300–86400秒，观察窗1–30天。普通触发不接受lifecycle，分析默认7天。

生日按UTC月日，闰日只在闰日命中；沉睡按最近完成下单间隔，无成交按入会天数；复购需历史净消费>0且达到完成下单间隔。加购按当前门店最新加购，已等待指定时长且该门店加购后无PAID/FULFILLING/COMPLETED订单。下单时间作为付款订单关联锚点，既有未付订单在加购前创建而加购后付款不算新购，界面说明此边界。

发布时创建持久扫描记录。每轮每租户最多20会员/最多5个到期版本，每版本最多4步，固定本轮创建截止，稳定会员游标，单会员入组和游标同事务。每轮最多4租户；版本公平游标避免一个扫描任务独占。结束后按扫描间隔开启新轮。错误退避，5次隔离，可按版本和原因重试；停止发布后不再扫描，已提交业务效果不撤销。

生日每年每会员一次；沉睡/复购按交易锚点+controls固定窗口去重；加购按最新加购锚点去重。跨版本仍受既有旅程频控。所有新入组和已有实例节点执行前使用当前会员状态及偏好；关闭journeyEnabled后取消后续执行，原因MEMBER_DISABLED。加购触达前再次核对已购买则CART_PURCHASED取消。

Node追加可空coupon `{definitionId,version}`与COUPON节点；受控券有效窗口须覆盖入组和最长执行期限。券来源JOURNEY，以实例/节点去重，副作用和节点检查点同事务。权益、券效果分别计数；不宣称权益成本已知。旅程频控独立于定向批次的发券间隔。

GET /admin/journey-scans?after=&limit=50 返回扫描游标、截止、下次执行、状态、累计扫描/入组、失败次数及版本。POST /admin/journey-scans/{id}/{version}/retry `{expectedVersion,reason}` 幂等，仅隔离任务可重试。原 /admin/journeys/pump同时推进扫描和实例。

## 效果比较

GET /admin/marketing-effects/journeys?storeId&from&to&after=&limit=50：按入组时间窗选择队列，返回旅程/版本、观察天数、独立入组会员、已观察完整窗口会员数、触达/权益/券次数、付费会员/订单、收款、成功退款、净收款、优惠承担、最后投影时间。一个会员在当前队列同版本以首次入组为锚点，订单下单时间必须在锚点后及观察窗内。同订单可出现在不同旅程/版本行，不可跨行相加；不是因果增量或ROI。

GET /admin/marketing-effects/deliveries 同查询参数：按批次创建时间选批次，按实际couponId关联订单，显示发放/跳过/撤销/保留、付费订单、收款/退款/净收款及券自身优惠。不是订单全部优惠。退款发生在选择窗外也冲减历史订单净收款。

以上from/to最多93天，after为服务端返回seriesId。分析投影追加memberId/couponId/couponDiscount；旧订单经现有分页rebuild补齐，响应注明事件/回填覆盖限制。营销分析仅同模块只读关联旅程/定向回执，权威订单仍经OrderApi/QuoteApi/RefundApi投影，不跨领域写表。

## 可信性补丁及验收

成长写路径改当前锁读，读接口保留普通读；真实MySQL旧RR快照+两笔不同退款验证成长/行为净额无丢失。生命周期验证生日/闰日、沉睡/复购、门店隔离加购、已付款排除、等待期间关闭偏好、重复/并发扫描、隔离重试及权限；效果验证真实支付/退款/重建不重复计数。前端支持生命周期参数、扫描状态、券节点及效果比较表。

## 发布兼容

V32仅追加结构与扩展检查约束，不改旧内容。新生命周期/COUPON定义须在所有旅程执行器升级后启用；旧执行器不认识新节点，不能混跑新定义。代码回退前暂停新旅程并停止其执行器；已发券/权益不会因镜像回退撤销。历史批次创建时间未知保持null，不能为分析伪造时间。当前8604为隔离验证实例，非生产发布。
