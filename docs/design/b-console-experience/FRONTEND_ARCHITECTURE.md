# B 端接口匹配与体验重构

## 目标、授权与工程边界

2026-09-30 用户授权：探查 B 端接口、完善接口与页面匹配、开始重构页面，并修复刷新清空缓存。品质目标为 Awwwards / Webby Awards / FWA 可获奖的设计水准；这是设计目标，不是已获奖、用户已审样稿或评委认可的事实。连续执行本地验证和持续授权的正常 Git 交付。

Brownfield：React 19.3、TypeScript 7、Ant Design 6.6.5、Vite 8.3；一个应用，一个 theme.ts 权威。沿用 Hash 旧工作台、固定 path 的中央 SSO 入口、既有 MySQL/API/幂等和服务端授权。不新增组件库、微前端、中间件、OA 逐笔审批或生产部署；会员商城只做会话恢复所需的兼容改动。

现有中央权限扩展属于另一任务，恢复入口保存在 delivery/b-console-experience/PREVIOUS_PROGRESS.md。本轮不把尚未接管的业务放入中央链，也不使旧凭据成为中央故障的回退。

## 可核实事实与风险

基线 654d903。控制器逐条读盘得到 193 条 B 端/身份 HTTP 映射、41 个控制器，原始清单见 ENDPOINT_INVENTORY.md。它是静态映射清单，不等于每条接口都已联调通过。

- App 的 token、actor 仅内存保存；刷新必然丢会话。登录只保留订单深链接，其他目标页被重置。
- 商品、订单、营销等列表的游标和页签仅组件态，刷新不能恢复。中央 OIDC 已使用 sessionStorage，不应再建立另一份中央凭据。
- RuntimeRecoveryController 的十个恢复/重放映射和 PlatformRuntimeController 的运行健康读接口已有真实后台能力，但无完整 UI。
- PLATFORM_OPERATOR 是后端真实角色，前端 Actor 类型/菜单未覆盖；旧 /me 对平台角色为 403，不能通过放宽租户接口来登录。
- 中央固定页面已覆盖商品、目录、库存、会员、标签、行为、成长、积分、周期、兑换、券、权益和规则，但重复独立页头、组织说明与布局，缺统一导航。
- 刷新后的数据必须重新读取，不能将浏览器缓存当库存、资金、权限或账本权威。

## 状态与刷新恢复

会话：旧 bearer 写入当前 tab 的 sessionStorage；刷新先恢复 token，再 GET 身份；不存 actor/权限作为准入依据。401 清除当前会话并卸载业务页；503/网络失败保留恢复机会、显示重试；退出清 token。存储被浏览器禁用时可继续登录，但明确刷新无法恢复。中央继续复用 OIDC sessionStorage。

URL：page/store 和适用 after/filter/tab 保持可恢复，更新查询不丢订单 ID；切业务页不携带前页游标，切门店清理对象/筛选/选择。敏感地址、token、编辑草稿、未知写意图不写 URL。URL 内容只是查询，不是授权。

服务端 state：沿用可取消 useResource/useCentral，身份/租户/对象改变隔离旧请求；刷新重读真实数据。局部 state：抽屉、勾选、临时表单和报价仍为临时态；恢复不自动重发业务命令。本轮刷新修复验收指已登录状态和查询上下文，不将未提交草稿或命令持久化成第二账本。

| 状态 | 页面行为 |
|---|---|
| loading | 保留框架、对象和任务名称，分区占位，不先显示「无数据」 |
| empty | 查询成功后的空结果；说明上下文和下一步，筛选可重置 |
| 401 / 403 | 401 返回登录；403 明确拒绝，不伪装空表/继承其他角色权限 |
| 5xx / network | 读请求可重试；恢复会话不清除凭据；写结果未知保留原键、体和对象 |
| validation / 409 | 定位字段；409 保留输入并提示核对新版本；不自动换键重复提交 |
| 202 / running | 显示已受理/运行中及真实标识，支持按实际 API 查进度 |
| success / partial | 回执确认后刷新；任务恢复逐项列明 APPLIED/REJECTED 和原因 |
| stale | 标明读取时间/口径，危险命令用原 API 的 expectedVersion，不凭缓存决定 |

## 视觉方向、配方与可观察品质

沿用用户「简洁精致企业工作台」偏好与蓝色品牌，具体布局为本轮设计假设。目标：安静的中性色框架、清晰的蓝色行动线索、中文可读排版与真实业务信息。装饰随任务收敛；总览体现经营，运行时体现证据/安全门，配置体现结构。

唯一 theme.ts：canvas #F6F8FB、surface #FFFFFF、ink #172238、muted #5B677B、accent #3455DB；状态深字浅底并保留文字。内容层级调整通过角色/页面配方，会员端品牌不重设。桌面正文14px、关键说明14px、数字 tabular-nums、页标题26px；主控件38px、行内32px；间距4/8/12/16/24/32/48，控件8px、内容面12px、浮层16px。焦点2px可见。

- 壳层：236px导航、64px上下文条、内容最大宽1600px，任务标题/分组/当前位置清楚。品牌图形是可重复的连通方格标记，少量线性图标。
- 总览：统计口径与读取时间靠近数字；一组关键经营指标、主趋势和会员/商品结构，快捷导航退至末尾，不使用虚构同比或任务数。
- 列表：页头→常用筛选/结果→表格→真实游标；金额/数量右对齐，名称优先，长标识可读/复制；次动作轻量，主动作突出。
- 详情：身份/状态先行，业务事实、明细、时间/版本/关联分组；复杂订单完整路由，快速比较抽屉；短单次命令 modal，长配置完整宽工作区。避免多层抽屉。
- 运行时：状态与证据表、受限操作、持续结果面板；试运行安全门与实际范围直接可读，不让原始 JSON 成为默认业务界面。
- 中央工作台：同一导航与表面系统，业务页保留独立读写工作区、原授权提示及离开保护。禁止通过统一壳层调用未经许可的门店/会员目录。

桌面1440/1280、既有窄屏390；桌面宽表自身滚动，窄屏导航折叠、浮层全宽且动作可达。图片用现有商品 API images，B 端无摄影需求，不新增外部字体/插画；中文系统字体回退，无加载抖动。新增导航动画若采用须低于200ms并尊重 reduced-motion；本轮默认复用无动画配置。

## 代表路径与反复自查

先验证「登录→商品查询→详情/编辑→保存/错误→返回→刷新」；再做「停止任务→证据→恢复→逐项结果→审计」「重放安全矩阵→试运行→创建→任务控制」「中央员工页→独立工作区→未知结果/退出」。全范围清单按页面族逐一检查，不以首页截图代表完成。

每轮保存当前代码摘要、视口、route、状态、截图和操作记录，实际查看整体与详情。自查：构图/排版/品牌识别、真实信息完整、按钮主次一致、可访问性/焦点、长内容/窄屏、返回/刷新恢复。发现偏差→修复→重截图/操作对应路径。硬门槛：无全页横向溢出、无白屏/控制台错误、403不当空态、202不当完成、金额/状态真实、表单动作可达、会话恢复不越权。文本对比4.5:1、大文本3:1按实际配色核验；截图与操作证据分别记录。

品质由具体偏差收敛与当前证据判断，不使用模型自评分宣称获奖。外部评委/用户审美认可为未验证；完整本地体验与可观察品质门槛为本次交付标准。

## 模块、契约与下游

shared/session 只负责旧会话与失效事件；shared/routeState 只负责可分享查询；app 承担角色导航；features/RuntimeOperations 与 PlatformRuntime 各用自己的正式 DTO；iam/CentralShell 仅布局，不持有/复用旧 token。原 feature 仍按业务模块组织，不引入全局业务缓存。

契约见本目录 CONTRACTS.md：既有运行时 DTO 字段从服务实现读取；唯一后端增量为平台自身身份读取。与 BACKEND_ARCHITECTURE 中跨租户指标和最小能力一致；无数据模型/迁移变更。设计一致性审查：无隐含 API、无第二设计体系、无新增中央能力，Gate PASS_WITH_ASSUMPTIONS（具体视觉样稿无用户确认，按用户授权自查落实）。
