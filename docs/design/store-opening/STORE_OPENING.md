# 商城店铺开通与经营就绪

## 对标与本期范围

淘宝的开店认证把主体核验纳入开店流程。京麦把公司、品牌及行业资质、费用查询和入驻进度作为独立事项。京东的供销平台区分旗舰店、专卖店、专营店等经营类型。商城据此把经营主体、资质记录、店铺启用和经营就绪分别管理。 [淘宝开店认证授权说明](https://terms.alicdn.com/legal-agreement/terms/suit_bu1_taobao/suit_bu1_taobao202203241732_90379.html) · [京麦开店指南](https://jm.jd.com/mobile/merchant_guide.html) · [京东供销平台](https://gxpt-front-pro.pf.jd.com/)

首批支持已有商家下由运营办理开店，记录申报主体类型（个人、个体工商户、企业）、店铺名称和一个主营经营类目。经营类目在平台两级字典中选择。审核在有权受理的现有流程完成，开店仅存审核记录编号。品牌型店铺需另签经营类型、品牌及授权链规则后再开放。交易和营销接入另有门禁，商城启用店铺不会自动开通外部渠道或试点结算。

## 技术与影响

| 已核对的未知项 | 取舍 |
| --- | --- |
| 草稿能否误入买家或运营门店选择器 | 在店铺权威记录新增待开店状态。店铺目录管理页可检索待开店记录，公开目录和经营范围查询排除草稿，现有成交前置校验继续只允许可用店铺。 |
| 支持独立入驻申请系统还是留在商城 | 当前由既有开店运营岗操作，复用店铺模块、MySQL、Flyway、已有命令收据和审计。身份校验、资质原件与外部平台授权继续由其权威系统管理。 |
| 中断、并发和存量兼容 | 草稿保存后可按业务编号恢复。改资料、确认开店均校验版本，启用与收据同事务。兼容旧直建 API 和历史单据，网页走开店流程。 |

## 操作和接口契约

入口为店铺管理或中央「商家与门店」的门店目录。填写基础资料、选择经营类目后保存草稿，按待开店筛选可继续。确认时复核所属商家以及所选类目均可用。开店主体代码是 `PERSONAL`、`INDIVIDUAL` 或 `ENTERPRISE`。经营类目来自 V83 初始化的数据库字典，和开店后门店自行管理的商品类目分别使用。开店记录同时保存代码及显示名称快照，历史手填资料可原样查看或在改草稿时改选标准类目。

| HTTP | 请求与结果 |
| --- | --- |
| `GET /v1/admin/store-opening-categories` | 返回可选二级类目及完整路径。 |
| `POST /v1/admin/store-openings` | `storeId, merchantId, name, subjectType, categoryCode` 保存为 `PENDING_OPEN`、版本 0。兼容旧客户端的 `category` 文本。 |
| `GET /v1/admin/store-openings/{storeId}` | 返回草稿或已确认的资料、版本、审核记录引用及开店审计字段。 |
| `POST /v1/admin/store-openings/{storeId}/revise` | `expectedVersion, name, subjectType, categoryCode` 补正待开店资料，版本加一。旧 `category` 文本仍可解析。 |
| `POST /v1/admin/store-openings/{storeId}/open` | `expectedVersion, reviewReference` 将对应待开店版本变为 `ACTIVE`，保存操作主体及 UTC 时间，版本加一。 |

开店接口沿用 `commerce.store.create` 及可信租户，中央入口需租户范围许可。命令使用 `Idempotency-Key`，同键异载荷及旧版本冲突返回 409。其他租户或无开店资料的记录返回 404。门店编号在租户内唯一。旧直建接口 `POST /v1/admin/stores` 保留给已有调用方。

V82 保留旧行与既有写入。开放首个新草稿前，所有对买家提供门店目录的节点都必须切至能过滤草稿的版本。存在待开店记录时，暂停新建可使用现有运营权限控制，买家目录继续由新版提供。需要回退到旧目录前，先处理草稿兼容及 Flyway 版本。

## 避免把开店误当成已开卖

| 谁确认 | 需要配置或核实的资料 | 可复核依据 |
| --- | --- | --- |
| 商城运营 | 商家与店铺绑定、开店审核引用、运营人员、买家能访问的店铺、首个上架商品和实际类目 | 开店记录、经营授权、目录查询、商品发布记录 |
| 交易中心与仓配 | 交易租户、商城门店与交易 SKU 映射、可售库存、支付能力、发货仓和退货地址；仅由权威路径管理可出售的同一份库存 | 隔离新单引用、库存预占、支付门禁和仓配范围 |
| 营销运营与资金 | 营销租户、组织与店铺映射、活动制品及版本、出资账户与币种、收退款回执权限 | 活动签价、同一原生单预留回执、成交与退款账证 |

三方试点按同一范围版本核对参与店、对照店、SKU、WEB、CNY、活动和出资。Auth 确认买家主体映射及受众，应用上线放行以实际的新订单和证据为准。保存草稿、修改资料或确认商城开店都不会自行变更试点范围。实际品牌授权、外部渠道资质、收付/履约和三方放行分别登记签收。

### 首店配置签收单

按一次试点范围填写一份。环境标识、范围版本、负责人与证据索引随签收记录保存。凭据只留受控引用。

| 资料 | 签收时核对 |
| --- | --- |
| 范围版本、参与店、对照店 | 商城 `COMMERCE_CHECKOUT_PILOT_*`、交易 `TRADE_CHECKOUT_PILOT_*`、营销决策 `MARKETING_CHECKOUT_PILOT_*`、营销资金 `CHECKOUT_FUNDING_*` 的 `SCOPE_VERSION` 都等于签收版本。对照店在参与范围外。 |
| 已开通的商城门店和规格 | 商城与交易的 `COMMERCE_TENANT`、`MERCHANT_ID`、`STORE_ID`、`SKU_ID` 对齐。交易 `SKU_LINKS` 包含同一商城规格和已签收的双侧规格版本，营销决策 `SKU` 和资金 `STORE` 使用同一商城规格及门店。 |
| 原生交易和营销映射 | 交易 `TENANT_ID` 等于其余三个服务配置的 `TRADE_TENANT`。交易原生商户、仓库和签收 SKU 有库存证据。交易的 `MARKETING_TENANT/ORGANIZATION/SHOP/CAMPAIGN/FUNDER` 对齐营销决策与资金服务的对应范围。活动记录绑定已审批的版本和出资账户。 |
| 买家与作业授权 | 保存隔离买家在商城与交易的对应关系、交易授权受众与交易 `MEMBER_LINKS` 核对结果。单独核对机器权限、主题、消费组和资金回执签名的密钥标识。 |
| 行为证据 | 参与店浏览器新订单有一份交易库存预占和营销预留，对照店走原路径。记录范围版本、商城报价、交易报价、原生订单、预留和支付意图引用。正式试点增加实际渠道的收款、履约、退款和日结。 |

## 验证

- 真实 HTTP 与 MySQL 验证跨租户、待开店隐藏、整数主体代码拒绝、版本和并发开店、幂等与历史直建兼容。
- 隔离浏览器验证新建、草稿刷新恢复、资料补正、审核确认及买家目录。新店上架单价 59 元商品并正常入库，买家两件报价为 118 元。开店表单在 1440 和 390 像素下可完成录入。
- 扩大到商家自助和指定品牌类型时，单独验收商家申请、审核岗退回与复审、品牌授权及经营就绪任务。
