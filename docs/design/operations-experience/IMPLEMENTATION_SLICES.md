# 运营体验改造实施计划

以 [运营审计路线图](../../audit/operations-experience/08-implementation-roadmap.md) 为起点。按先修正操作者看到的范围和查询、再增加权威信息、最后衔接跨域作业的顺序推进。首批复用 [查询契约](../frontend-usability-queries.md)、现有中央页面壳和权限边界，同一任务分支按可回退切片提交。前端沿用 Ant Design 和工作台样式。后续列表将业务名称、编号、状态、组织与时间作为独立列，窄屏通过表格内滚动查看辅助列。

| S1 · UX-01 | 企业账号可直接访问组织入口壳并按本人可见导航落地 | Spring MVC 精确 GET 路径与安全白名单。现有组织、回调、访问与导航契约 | 真实 HTTP 的页面壳、未知路径拒绝、POST 拒绝、匿名业务 API 拒绝。中央导航公开 DTO 浏览器落地 | 现成中央入口 |

S1–S5 是本次开始执行的第一批，串行关闭每个可验收结果。这批修改使用当前的 API 字段、业务状态与服务端权限。测试采用隔离本机库、直接 HTTP、可用演示读取或中央公开 DTO 的边界测试。真实 PKCE、跨租户角色、正式渠道及治理风险按 [风险文档](../../audit/operations-experience/05-operation-risk-audit.md) 在有相应环境的切片验证。进度见 [PROGRESS_STATE](../../delivery/operations-experience/PROGRESS_STATE.md)。

S6 的第一条用户路径是按准确门店查看订单。现有关键词可部分匹配门店编号。新契约需清楚表达精确店铺参数、列表角色数据范围、未知或越权门店行为、返回时游标重置与旧客户端兼容。权限核对排在分页之前。
