# 全站居中弹层与统一按钮

用户于 2026-10-02 确认本方案。适用经营台、中央权限页面、门店协作和会员商城。

## 设计取舍

使用 Claude 官方插件的 `frontend-design` SKILL，沿用商城已有视觉体系。以订单、商品和会员的业务内容为主，操作区保持一致，便于用户从列表进入详情、编辑后返回。

| 角色     | 色值      |
| -------- | --------- |
| 画布     | `#F6F8FB` |
| 内容面   | `#FFFFFF` |
| 正文     | `#172238` |
| 次要文字 | `#5B677B` |
| 分隔线   | `#E3E8F0` |
| 主操作   | `#3455DB` |

字体沿用系统中文字体栈（PingFang SC / Microsoft YaHei）。正文与按钮 14px，弹层标题 16px。内容左对齐，弹层在视口水平、垂直居中；编辑动作放在底部，长内容独立滚动。

```text
背景列表（保留游标与筛选）
       ┌─────────────────────────────┐
       │ 业务标题    展开视图    关闭 │
       ├─────────────────────────────┤
       │ 详情 / 表单                 │
       │ 内容区独立滚动              │
       ├─────────────────────────────┤
       │                  取消  保存 │
       └─────────────────────────────┘
```

对照需求后，采用现有颜色、字体和业务分组，将变化集中在弹层位置、可滚动内容和按钮度量。移动端导航也使用居中弹层，不保留侧滑抽屉。未增加字体、依赖或新的设计系统。

## 当前实现规范

- 用户反馈弹层过大后，统一收紧普通 Modal 与共享 `RecordModal` 的尺寸。普通详情默认宽 560px；编辑表单通常 600–640px，表格/关系图详情不超过 760px。只有用户主动展开共享弹层时才增加至 960px；旅程详情不再默认展开。
- 导航弹层宽 400px，无展开按钮和默认详情页脚。购物袋宽 520px，商品详情宽 720px；手机购物袋步骤采用横向排列与图标下方标题，缩小商品图和缺图占位。
- `ConfigProvider.modal.centered` 覆盖现有普通弹窗及上下文确认框；共享弹层显式 `centered`。
- 所有操作按钮高 38px、字号 14px、圆角 8px、左右内边距 14px。文字决定宽度；仅图标按钮宽 38px、内边距 0。按钮度量统一定义在 `theme.ts` 的 Button token 中。
- 移除页面 `Button.size` 差异和行操作、会员端、购物页的 CSS 尺寸覆盖。商城分类使用同一 Button；搜索框的内置按钮保留完整圆角并与输入框分开。
- 商品图片、商品标题、趋势图和旅程节点保留其可交互内容形态，它们不作为普通操作按钮缩成 38px。
- 短内容按内容高度收缩，没有统一最小高度。桌面普通弹层高度上限为 `min(76dvh, 680px)`，主动展开上限为 `min(88dvh, 820px)`；窄屏上限为 `min(82dvh, 640px)`，两侧留白16px。只有内容区滚动，标题与页脚不参与滚动；窄屏隐藏没有额外阅读空间收益的展开入口。
- 标题16px、圆角12px、桌面内边距20px/手机16px；标题下留白12px，表单项目间距16px，页脚上下分隔12px。保持业务字段完整和38px按钮，不通过裁切内容实现缩小。
- 原关闭保护、请求中禁止离开、未知结果原请求重试、销毁、焦点归还和接口契约保留。运营页面与旅程编辑器在内容挂载完成后按当前草稿初始化，防止新建使用上一版本初值。

## 验证与证据

验证状态记录在根目录 `CODEX_PROGRESS.md`，本任务浏览器 JSON、截图及交付回执位于忽略目录 `.local/frontend-modal-buttons/`。界面测试只在接口边界返回正式 DTO，不在产品页面硬编码演示数据，也不把界面夹具当作真实授权、PKCE 或资金业务验收。

`tests/presentation.ts` 检查真实渲染的按钮高度、字体、圆角、内边距，以及弹层实际位置与视口边界。中央全部路由覆盖 1440px、390px、320px；代表性活动详情/编辑、移动导航、商品详情与结算覆盖焦点、内部滚动和关闭保护。已有中央交互回归与远程真实业务 CI 另行记录，未执行的真实 PKCE 用例明确跳过。

紧凑样式回归增加普通详情、商品详情与购物袋的实际宽高上限，并等待入场动画结束后核对位置和截图，避免将只有遮罩的过渡帧当作最终视觉。当前紧凑样式证据位于 `.local/compact-modals/`。

此前 `frontend-interaction-refresh` / `frontend-visual-refresh` 下的抽屉与 32px/44px 按钮验收属于历史证据；现行组件和尺寸规范以本文件及源码为准。
