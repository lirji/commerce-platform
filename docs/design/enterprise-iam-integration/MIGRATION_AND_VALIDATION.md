# 身份权限迁移、灰度、故障与验收计划

- 状态：PROPOSED；下表是未来 MUST 验收，**本轮没有执行这些业务测试或迁移**。
- 适用：IAM-01–16；物理迁移 IAM-17 另有就绪门禁。范围、关键决定与候选契约见 [整体方案](README.md)、[架构](BACKEND_ARCHITECTURE.md)、[契约要求](CONTRACT_REQUIREMENTS.md)。

## 1. 迁移边界与单写原则

迁移按“企业＋应用＋环境＋资源／动作／路径”的明确范围进行。身份映射、角色与范围、对象关系、UI 和鉴权路径分别有版本，不能一次性把所有消费者／旧账号／权限表改成新模型。

| 对象 | 扩展与回填 | 共存与追平 | 切换／退出条件 |
|---|---|---|---|
| 身份与成员关系 | 保留 Casdoor sub 和原 actor/member；建立绑定与来源映射 | 以来源版本／员工事件或公开查询补齐；重复不重建主体 | 映射完整、冲突隔离、原订单／会员关联一致；未绑定不能后台访问 |
| 应用与权限目录 | 新增 app/env/client mapping、稳定权限点及角色版本 | 旧权限名称可映射，禁止无来源的角色自动扩权 | 目录覆盖真实 API；被切换接口的旧／新允许语义经审核 |
| 商城商品经营授权 | 读取现有授权＋业务归属形成比对；不裸写其他库 | 切换前旧服务唯一写；变更通过可靠桥进入新读模型 | 授权／撤权／到期／未来门店继承对账完成；切换后旧管理入口变兼容门面 |
| OA grant 与范围 | 增量 app/env/member 字段或新模型，不修改历史迁移 | 旧授予来源可追溯；新旧引擎处理同一规范授权版本 | 老 API 兼容，角色动作与范围关联不被扁平化，epoch 语义确认 |
| SpiceDB 对象关系 | 保留现有工作区 schema 和 tuple ID 前缀 | 一期不迁实例；治理通过原端口写，确认水位与审计 | 若未来迁模型须单独全量＋增量方案；schema/write 整体替换不得误删其他 definitions |
| SDK 与页面权限 | 增量版本／门面，按接口与应用接入 | 旧 SDK 与新客户端版本同时回归；UI 摘要可更新 | 服务端 guard／Mapper／任务实际执行后才启用对应菜单与按钮 |

可靠桥必须在回填开始前定义如何接收源变更，记录稳定高水位、游标、幂等键和撤权墓碑。按租户／应用有界分批，checkpoint 与批次提交一致；并发更新／删除不能被旧回填覆盖。

校验包括同一源版本／水位下的映射数、授权数、条款摘要／checksum、角色来源和业务不变量。不只比较“用户数一样”或 HTTP 200。旧写入口关闭与新写入口开放由单个可审计的迁移状态控制，禁止两个 best-effort 写入同时成为权威。

## 2. 灰度状态与路径选择

```text
DISCOVERED → MAPPED → SHADOW → VERIFIED
           → CANARY_READ → CANARY_WRITE → ACTIVE
           → LEGACY_READ_ONLY → RETIREMENT_REVIEW
```

每个状态有当前版本、进入证据、失败条件、回退状态与负责人。初始为 DISCOVERED，所有业务执行证据 NOT_RUN。停止旧接口、删除旧表或认证凭据属于独立清理任务，本轮没有自动清理步骤。

- SHADOW：旧路径唯一执行实际行为，新路径只计算身份／动作／范围／对象决策；不写 grant、业务库、支付、审批或第三方副作用。判权审计也须隔离或明确标记影子来源。
- 差异分为身份映射错误、旧规则较宽／较窄、目录缺失、范围变化、业务规则变化、故障／新鲜度错误。安全差异必须有逐项解释，不能以整体一致率掩盖一例额外放行。
- CANARY_READ：先显式应用／主体队列，比较可见集合、分页／count、字段、附件；不能读到本不允许的数据作为“观察”。新路径应通过隔离测试后才可处理真实试点。
- CANARY_WRITE：只在当前动作、范围、版本、新鲜度和回退验证全部通过后开启。用选定业务用例验证；不复制执行订单、退款或审批。
- ACTIVE：明确由新门面单独执行当前路径；其他路径保留现有规则；不使用 oldAllow OR newAllow。非试点的旧接口不会自动开放给新角色。
- 物理进程合并或更广泛生产放量：使用新计划、运行目标和批准记录；当前不指定停机或流量百分比来伪造可执行切换。

## 3. 撤权、新鲜度与在途边界

撤权以“权威变更已登记”和“应用执行路径已满足目标版本”分开报告。下游只按新的 revision 更新；过期、删除和停用使用墓碑／状态，旧消息或旧回填不能恢复授权。

Q06 必须冻结各动作类别的撤权时间目标、缓存最大租约、时钟偏差、不可用行为及授权线性化点。源端提交成功、清 Redis、通知已发或本机一条 Check 拒绝，都不能证明跨实例已收权。

对已确认生效后的**新请求**，要求适用应用拒绝该授权。已开始请求以正式契约约定的最后授权检查／受理提交点区分：若要求在业务提交前强制中止，要有可验证的事务内栅栏或等价机制；跨服务“先 Check 再写库”本身不提供撤权与业务提交的原子性。

| 操作类型 | 建议边界 | 必须验证 |
|---|---|---|
| 新敏感写入、授权管理、敏感字段明文读取 | 使用权威状态／新 revision 或适用对象水位；无法证明则不可用／拒绝 | 两节点、断连、旧快照、源端失败、请求与收权并发；具体提交语义按 Q06 |
| 普通读取 | 若允许缓存，必须有已确认的最大租约；未确认前不许无限沿用 | 失效消息丢失、TTL／租约到期、服务重启、旧读取回填、时钟偏差 |
| 外部到期／邀请过期 | 每次校验服务端时间和关系／授权窗口 | 关闭清理任务仍拒绝到期用户；续期与旧请求／旧消息竞争 |
| 用户发起的导出、批量编辑等任务 | 入队与每批／每个新副作用前重检；记录发起人、授权条款、范围及版本 | 入队后撤权、执行中变更范围、取消／恢复、部分完成、下载时再次校验 |
| 支付对账、库存释放、既有业务效果补偿 | 用受限服务主体履行系统责任；与用户新操作分开 | 员工离职后必要补偿仍恢复；不能借此扩大服务账号权限 |

恢复身份、续期或角色重新授予都是新决策，不恢复旧 grant ID 的历史有效状态。日志记录真实状态和原因，不能写“撤销成功”同时仍让旧缓存无界继续允许。

## 4. 每步回退与中止

| 触发 | 中止动作 | 回退与数据处理 | 通过回退的证据 |
|---|---|---|---|
| 多企业／跨应用／越范围额外允许 | 立即停该应用／路径放量 | 选择已验证兼容版本；保留最新禁用／revision；必要时暂停相关准入 | 负向用例、真实接口和两实例验证 |
| 身份映射冲突或未绑定 | 隔离对应主体，不创建重复会员 | 停新绑定，保留原 ID 与原业务数据；核验身份后受控补齐 | 原订单／积分／幂等回执关系校验 |
| grant／关系桥部分失败 | 保持授权非完成，拒绝需新鲜状态操作 | 根据 changeId 和源版本重试／对账；不再写第二份不受控授权 | 断点恢复、单写与来源对账 |
| schema／SDK／API 不兼容 | 停切换，不停未受影响应用 | 回旧门面；新增列兼容保留；不修改历史迁移 checksum | 旧新应用／SDK 并存验证 |
| 延迟、错误率或资源预算超出确认目标 | 暂停扩展 | 回该应用队列的兼容路径；限制范围／批次，复核缓存与数据库负载 | 有基线、目标和同范围量测 |
| 外部准入或邀请异常 | 停邀请与外部受影响准入 | 撤销错误条款，记录已读／已提交效果；不能宣称代码回退删掉已经泄露的数据 | 单次接受、管理上限、两合作方隔离 |
| 回退版本不识别新撤权 | 禁止回到该版本 | 保持拒绝或升级兼容回退包；不能回滚授权版本为旧值 | 撤权后回退仍拒绝、旧节点不参与判权 |

回退分为代码／路径、契约／配置、schema／数据和业务补偿。已经发生的资金、库存、审批、导出结果按业务补偿和数据治理处理，不靠镜像回退撤销。删除旧表／旧入口需明确批准、备份、恢复验证和消费者退出证据。

数据来自可清理的隔离数据库 seed：至少两个企业上下文、两个应用、两组资源、内部／外部／消费者／服务主体及旧新版本。仅为验证硬隔离使用第二企业测试夹具，不宣称一期已建设完整多企业商业 SaaS。测试数据不得放到生产或写死前端。

原构建与业务测试按各仓规范运行：commerce 复用真实 MySQL 与浏览器 CI；OA 用其 system Maven 和批准的隔离运行目标／冒烟、golden、架构覆盖；auth 用现有协议／HTTP 适配／SDK 与针对工作区的冒烟。首次运行先确认数据库和 schema 写入目标，禁止把全量替换脚本指向共用工作区。

## 6. 切换门禁、运行指标与证据

切换门禁包含：当前版本构建、相关业务回归、协议兼容、映射与授权对账、事务／并发、影子比较、负向越权、撤权／故障、时延／容量、日志审计、回退、目标环境与批准。任何 MUST 失败停对应范围的放量。

需要确认／量测的指标：接入应用与活动主体数、授权与范围大小、Check/Scope 峰值请求及 P95/P99、授权生效／撤权时延、最大读模型租约、失败与分发积压、缓存回源／数据库上限、运行可用性、恢复点和恢复时间。当前数值 UNKNOWN；不得把旧源码注释或本地历史测试当成新平台生产达标证据。

每项 TEST_RESULT 记录执行命令／场景、环境、版本、预期与实际、负向断言、日志／数据库观测、失败恢复和限制。文档检查 PASS 只表示本轮计划一致性检查完成，不替代上述验收。

## 7. 风险登记与重新规划

| ID | 风险 | 具体失败场景 | 主要控制与解除证据 |
|---|---|---|---|
| R01 | 身份错绑 | 同邮箱被当作同人，历史会员改归属 | verified issuer/sub 映射，冲突隔离，V05/V06 |
| R02 | 应用／企业串权 | 项目等于租户，头部任意切换，ADMIN 全局继承 | 显式命名空间与可信上下文，V01–V04/V10 |
| R03 | 授权范围放大 | 多角色把读 A 与写 B 合成写 A | 保留动作范围关联，V09 |
| R04 | 管理员自扩权 | 角色编辑者加敏感动作再授自己 | 独立可授予上限、审批分离，V11/V12 |
| R05 | 外部退出遗漏 | 邀请重放、合同失效但授权长期存活 | 成员／合作方状态与窗口，V13–V15 |
| R06 | 旧缓存／水位继续放行 | OA epoch 失败沿旧值，auth 仅本机记写水位 | 风险分类 freshness、跨实例证明，V22–V25 |
| R07 | 迁移双权威／回填复活 | 两边独立写 grant，旧数据覆盖撤权 | 单写状态、可靠桥、墓碑、对账，V24/V28/V31 |
