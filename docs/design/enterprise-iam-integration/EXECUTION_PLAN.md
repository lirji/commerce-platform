# 企业 IAM 建设与项目接入执行计划

- 状态：PROPOSED；本轮只有计划文档完成，以下 IAM 切片均未执行。
- 任务范围：三个仓库的身份与权限接入。生产部署、删除旧认证／授权、修改历史迁移、物理数据库合并不在本轮授权内。
- 每个切片执行前冻结所属方案、正式契约与可观察验收；跨仓任务在各仓创建独立任务分支，按依赖发布协议和消费方；保留已有脏改动。

## 1. 执行与协作职责

| 职责 | 负责确认与交付 | 典型结果 |

## 2. 基线与业务冻结 P0

### IAM-00：确认业务边界与试点矩阵

- 依赖：无。Owner：企业身份负责人＋应用负责人。仓库：三仓只读，设计主记录在 commerce。
- 输入：本计划、现有 OA 治理设计、auth 工作区与协议、商城 Actor/SQL，Q01–Q07。
- 交付：确认企业隔离、员工／外部／消费者关系、应用清单、试点角色动作范围矩阵；逐项标注现有／新增权限和资源；确认 high-risk 策略、身份映射、现状构建／权限测试与所需运行基线。
- 验收：至少同人两应用、内部两门店、外部两合作方、消费者本人四种负向用例有明确预期；授予上限、作用域与来源无歧义；确认的默认政策有负责人。
- 失败／回退：未知资源关系不开放；保留原数据与授权。尚未涉及权威或业务流量改变。

## 3. 身份与应用目录 P1

### IAM-01：企业、应用、环境与客户端目录

- 依赖：IAM-00。Owner：IAM 工程负责人。仓库：OA；auth 映射增量适配。
- 交付：Application/Installation/ClientMapping；每应用负责人、权限发布身份、接入能力版本；Casdoor organization/workspace 与 tenant/app/env 的显式映射；治理页面应用选择与管理范围。
- 验收：同企业两应用独立准入；测试客户端与生产作用域不可交叉；appId 不等于企业；现有工作区路由不被覆盖。
- 失败／回退：新登记保持未启用；保留旧工作区与客户端；新增结构兼容保留。

### IAM-02：统一身份、成员关系与员工适配

- 依赖：IAM-00。Owner：IAM 工程负责人＋企业身份负责人。仓库：OA。
- 交付：IdentityBinding、TenantMembership；员工投影经 OrgDirectoryPort；独立外部人类入口；旧 USER/Casdoor subject 兼容；同人多个成员关系；不再用 activeUser 员工查询验证全部人类主体。
- 验收：员工投影幂等；外部无需员工行；同邮箱不同来源不自动合并；调岗／离职只改变对应关系；身份恢复不恢复撤销授权；数据迁移注释、唯一约束和回填对账符合规范。
- 失败／回退：未核验映射隔离；新外部准入停用；原员工主体与业务记录不改 ID。

### IAM-03：认证、上下文选择与应用准入

- 依赖：IAM-01、IAM-02。Owner：应用工程负责人＋IAM 工程负责人。仓库：auth、OA；消费方按后续切片接入。
- 交付：按环境注册试点客户端、PKCE 登录、受众与 issuer 校验、可信成员／应用上下文、会话与凭据退出能力；一个入口展示可进入的应用。
- 验收：错误 issuer/aud/env、未绑定／未准入、失效成员被拒绝；登录到 OA 不能带未经允许的凭据调用商城管理 API；跨 client 的 subject 映射有证据；真实安装版刷新／退出行为验证。
- 失败／回退：客户端和新准入保持未启用；不重置用户密码、不覆盖其他应用配置、不把无绑定身份映射成管理员。

## 4. 统一授权与协议 P2

### IAM-04：权限目录、应用角色与管理上限

- 依赖：IAM-01。Owner：应用负责人＋IAM 工程负责人。仓库：OA、auth 治理适配。
- 交付：permission manifest、版本化角色、权限风险、接口／菜单／按钮映射、可授予策略、角色冲突与审批规则；角色变更预览。
- 验收：相同 roleCode 跨 app 不串权；应用负责人不能改别的目录；管理上限限制敏感动作、范围、时间窗和自批；权限目录未发布则接口拒绝；角色版本扩权不是静默完成。
- 失败／回退：拒绝发布有冲突目录；旧目录保留；撤权和生命周期状态不回退。

### IAM-05：授权条款、动作范围与审批

- 依赖：IAM-02、IAM-04。Owner：IAM 工程负责人。仓库：OA。
- 交付：角色版本＋per-action/resource scope bindings＋时间窗＋来源；申请／四眼审批／JIT／受限委托；单一授权写入口和审计；旧 grant 增量兼容。
- 验收：门店 A 只读与 B 可写不扩大到 A 可写；重复批准不重复授予；审批中角色／管理上限变化重新校验；过期即时受时间窗限制；组织／岗位与个人授权来源可分别收回。
- 失败／回退：保持申请／授权非 ACTIVE；兼容扩展保留；已撤销不因审批重试复活。

### IAM-06：统一契约、SDK 与引擎门面

- 依赖：IAM-03、IAM-05。Owner：IAM 工程负责人。仓库：auth 协议／SDK、OA 门面。
- 交付：冻结 [候选契约](CONTRACT_REQUIREMENTS.md) 为正式版本；可信调用者与代人限制；CheckAction/CheckObject/ResolveScope；保留 auth 九项操作；公开协议模块不依赖 OA 内部实体；旧 SDK 回归与服务权限。
- 验收：伪造 principal/app/tenant 不放行；响应缺字段／错资源／不支持类型不放行；组合必要约束不是 OR；原 SDK 和 OA API golden 兼容；新版本制品先发布再升级消费方。
- 失败／回退：保留旧 SDK 与契约门面；新客户端不准入；依赖故障返回不可用且无宽权限回退。

### IAM-07：数据范围规范与业务适配端口

- 依赖：IAM-06。Owner：应用工程负责人。仓库：OA、commerce。
- 交付：按动作的 ScopeDecision、声明范围映射、SELF 绑定、受管查询与写入守卫、字段权限；OA PG 适配与商城 MySQL 适配分别实现；范围能力上限。
- 验收：tenant＋范围在分页／count 前执行；join/聚合/详情/附件／导出覆盖；未知范围 NONE/拒绝；大范围有界；角色范围不串动作；无 SQL／字段原始输入。
- 失败／回退：停用未完成的资源／动作；新 API 不返回全量；不替换其他已验收业务的 Mapper 框架。

### IAM-08：可靠变更、生命周期与撤权证明

- 依赖：IAM-06。Owner：IAM 工程负责人＋运行负责人。仓库：OA、auth，消费方登记协议能力。
- 排程：可与 IAM-07 按不同路径工作，两者不互相作为前置。
- 交付：change/revision/receipt、可靠意图与幂等推进、epoch 与 ZedToken 适配、按风险的 freshness／租约、到期校验、断连恢复、成员关系／应用准入撤销；Q06 形成验收目标。
- 验收：两实例跨节点撤权；消息重复乱序；节点离线再启动；旧 L1/L2 回填；权威版本读取失败；已登记与已生效区别；过期不依赖后台清理；回退不恢复旧授权。
- 失败／回退：阻断敏感新操作，显示待处理应用；可靠记录留存并恢复；回退到能识别新 revision 的兼容版本，不能回到不知撤权的旧版本。

## 5. 商城内部人员试点 P3

### IAM-09：商城认证与旧业务身份桥

- 依赖：IAM-06、IAM-08。Owner：商城工程负责人。仓库：commerce。
- 交付：新 OIDC/准入适配，identity→原 actor/member 映射，公开授权端口和按路径灰度；TokenFilter、路径白名单、Actor 与业务层 guard 的兼容清单。
- 验收：会员／订单 ID 与原幂等回执不变；消费者仍限本人；新运营角色不通用映射成 ADMIN；未接入接口保持旧规则并不向新细分人员开放；legacy token 只在明确允许路径／期限内有效。
- 失败／回退：关闭新认证试点客户端或人员队列；原身份与业务数据保留；回退仍受停用／撤权阻断。

### IAM-10：内部商品运营完整纵向链路

- 依赖：IAM-07、IAM-09。Owner：商城工程负责人。仓库：commerce；OA 管理端发布试点授权。
- 交付：门店 A 商品列表、详情、编辑／上下架的一条链路；按真实 API 清单接入服务 guard、Mapper、路由／按钮、审计；现有 store grants 的单写与兼容策略。
- 验收：能执行 A 内获准动作；B 的直接 URL/HTTP/详情/修改被拒绝；字段不能伪造门店归属；查询分页正确；写入影响行数与乐观锁；门店授权撤销后新操作拒绝；数据库 seed＋真实浏览器验证。
- 失败／回退：仅回退该路径的灰度；保持旧授权权威或切换后的兼容门面，不能两边独立写入。

### IAM-11：订单客服读取与敏感字段

- 依赖：IAM-10。Owner：商城工程负责人＋业务负责人。仓库：commerce。
- 交付：按门店的订单列表／详情／总数，敏感地址与联系方式独立权限／审计；消费者原查询路径回归。退款写入不随本切片默认开放。
- 验收：跨门店订单不能通过 ID 枚举或统计泄露；列表／详情相同范围；无明文权限仅脱敏；跨租户拒绝；消费者仅本人；新的 staff 范围不借用会员 SELF。
- 失败／回退：停用新客服读取入口／明文动作；已导出或已读取数据不能宣称通过代码回退撤销。

## 6. 外部人与消费者 P4

### IAM-12：合作方邀请与限域运营

- 依赖：IAM-05、IAM-08、IAM-10。Owner：企业身份负责人＋IAM／商城工程负责人。仓库：三仓按边界修改。
- 交付：合作方登记、担保、单次邀请、独立外部成员、应用准入、审批、限时商品运营、复核／续期／收权；首期只用已存在商家／门店关系。
- 验收：两合作方之间隔离；拒绝转授与超限范围；到期、合同暂停、担保变更可收权；邀请重放／身份替换失败；不进入 OA 员工功能。供应商订单等新业务关系未实现时保持未开放。
- 失败／回退：关闭邀请与外部准入；保留主体和审计；已接受邀请不因重复请求扩权；外部撤权继续生效。

### IAM-13：消费者认证与会员绑定

- 依赖：IAM-02、IAM-03、IAM-09。Owner：商城工程负责人。仓库：commerce；auth 客户端与身份映射适配。
- 交付：消费者登录入口、最小身份绑定、原会员关联、自助基础策略、消费者与工作上下文隔离、封禁／会员状态协作。
- 验收：两个消费者本人数据隔离；绑定不重复建会员；用户自选 app/tenant/memberId 不改变本人；员工工作角色不进入普通购物；Q02 中离职与消费者账户规则有真实用例。
- 失败／回退：停止新消费者绑定／客户端；原会员、订单、权益记录不删除；封禁与收权不得回退。

## 7. 跨应用验证与推广 P5/P6

### IAM-14：OA 作为应用消费统一协议

- 依赖：IAM-07、IAM-08、IAM-09。Owner：OA 工程负责人。仓库：OA。
- 交付：OA app namespace、MePermissions/治理入口一致、现有 RequiresPerm/DataScope 兼容适配；员工投影及本地热路径保持；外部可访问功能通过明确准入控制。
- 验收：现有审批／待办／组织／考勤权限回归；新 API 带注解与权限点、golden 更新；PG org_path 过滤保持；非员工不能因统一登录进入员工功能；旧 subject 不改。
- 失败／回退：按 OA 路径回退到兼容门面；不覆盖组织表或执行 schema 全量替换。

### IAM-15：两应用端到端权限与用户体系验收

- 依赖：IAM-11、IAM-12、IAM-13、IAM-14。Owner：验证负责人＋各应用负责人。
- 交付：[验收矩阵](MIGRATION_AND_VALIDATION.md) 的当前版本证据；同人多角色、多成员关系、跨 app/aud/env、管理员限制、撤权、长期任务与失败恢复。
- 验收：OA 审批角色不给商城订单权；商城运营不给 OA 人事权；解除商城准入不撤销合法 OA 角色；员工关系结束在两应用员工上下文生效；全局封禁按 Q02 阻断所有相关关系；所有 MUST 通过。
- 失败／回退：停止对应应用／主体队列放量；记录问题，不使用另一套引擎“补放行”。

### IAM-16：受控推广、运行与接入手册

- 依赖：IAM-15。Owner：运行负责人＋IAM／应用负责人。
- 交付：每应用注册与接入模板、当前协议／SDK 版本、角色清单、数据范围能力、失效能力、审计看板、变更积压／期限监测、值班恢复和备份／回退步骤；Q07 指标确认；本地／测试验证与生产批准记录分开。
- 验收：下一应用可按模板接入；应用独立门禁；权限变更失败可定位应用／版本；发布与恢复证据绑定精确版本；容量、故障及目标环境达标才能生产切换。
- 失败／回退：按应用关闭扩展；保留撤权事实与兼容数据；生产部署通过单独执行任务，不由本次写计划触发。

### IAM-17：可选仓库／进程收拢评估

- 依赖：IAM-16。状态：OPTIONAL_DEFERRED。Owner：架构／运行负责人。
- 触发：两个应用已证明统一协议复用；出现实际发布耦合、运维重复或统一部署诉求。
- 交付：带所有权、调用依赖、运行量测和回滚的边界评估；选择同仓模块、保留部署或有证据的进程合并。现有 auth SDK、SpiceDB schema 与 OA 业务不直接拼接删除。
- 验收：架构决定可回放、迁移前置门禁通过，后续计划依赖有序；数据／API／流量有兼容、对账与回退。未通过则保持现有部署。

## 8. 实施交付与检查点

每切片建立本仓任务分支，实施、测试、迁移和必要文档作为可审查单元提交；按照用户持续 Git 授权正常合并／推送 main，远程失败或保护规则阻断时如实记录，禁止强推或夹带旧脏改动。多仓协议先发布兼容版本，消费方后切换；没有生产部署授权。

检查点包含 sliceId、三仓 commit、契约／目录／映射版本、测试结果、数据回填与变更水位、已灰度路径、未解决问题和回退版本。业务／权限规则变化或源代码漂移使旧证据失效，重新评估受影响切片。

“全部已完成”的判据是各 MUST 验收通过且交付可追溯，不以登录成功、菜单隐藏、进程健康、事件已发送或一条 Check 返回 ALLOW 代替权限闭环。
