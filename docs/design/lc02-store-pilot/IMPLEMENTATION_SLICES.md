# LC-02 首店范围实施计划

本计划细化 LC-02 的店铺范围和订单归属。用户已授权按当前方案执行。依据[改造方案](BACKEND_ARCHITECTURE.md)、商城[已有目录契约](../unified-commerce/s4/CONTRACTS.md)及营销[试点签收清单](../../../../marketing-lowcode-platform/docs/delivery/lowcode-commercialization/READINESS.md#lc-02-试点签收单)。新写入关系或对外字段在对应切片签收后进入实现。

## 1. 实施顺序

| 切片 | 结果 | 前置 | 负责项目和改动范围 | 完成条件 |
| --- | --- | --- | --- | --- |
| **LC02-S1 门店与商品核验** | 有一份可重查的商城候选范围及缺项记录 | 已获授权的读取环境和身份。未提供正式环境时可先验证隔离读取及整理缺项 | Commerce `merchant`、`store`、`catalog`。使用既有查询和分页，保留环境、精确 ID、状态、版本及来源引用 | 参与和对照店属于已确认的同一组织，参与店商户与门店有效，指定 SKU 在参与店已发布。冻结、错租户或查不到的结果可定位 |
| **LC02-S2 跨项目配对与下单取证** | 一版待签收的租户、商户、组织、门店和商品映射，并确定逐单门店证据入口 | S1 的可核验标识，以及交易和营销的对应标识 | Commerce `order-runtime`、`transaction-center` 订单入口、营销资金现有绑定合同。以双方持久记录核对一笔同源隔离订单 | 能从原生交易订单精确定位到经过验证的商城门店和范围版本。明确记载现有入口是否足以证明，以及缺哪一侧的记录 |
| **LC02-S3 条件补齐逐单门店关联** | 签名和绑定前可取得稳定、可复核的门店来源 | S2 证明确有缺口。写入方、调用方、时序和契约获签收 | 由掌握关系的可信下单入口负责写入，以已有持久引用优先。需新字段或表时由所属仓独占迁移链，调用方随后接入 | 实际数据库验证同订单同关系重试、改挂门店冲突、错租户拒绝、部分失败可补查及旧订单兼容。S2 已满足时登记复用证据并跳过本片 |
| **LC02-S4 授权核对** | 独立机器身份可在单一试点范围取得所需授权 | S2 明确租户与参与门店配对，以及 Auth 和资金负责人批准本次授权 | `auth-platform` 负责机器身份。资金服务消费现有 Casdoor 授权模型，核对部署配置和交易证据访问范围 | 有效令牌可用。错误主体、受众、租户、组织、门店与撤销后的凭据被拒绝。对照店范围仅留给测试核验 |
| **LC02-S5 营销单店接线** | 范围被用于校验满减配置、可信报价和订单绑定 | S2、S4，以及 S3 验证通过或具备可复用证据 | `marketing-lowcode-platform` 的 Workbench、Control、报价接入和资金绑定。用原格式配置单店单 SKU 方案，仅补实际缺少的范围校验 | 参与门店指定 SKU 达到门槛时命中，其他 SKU、对照店、未知来源和错租户保持未命中或按既有契约拒绝。签名订单号、门店和活动版本可核对 |
| **LC02-S6 隔离联调与范围移交** | 签收人收到一份可复核的试点范围验收记录 | S5、隔离环境及所需候选制品。正式签收另需真实环境和责任方 | 经已核验的下单入口发起订单，商城验证来源，交易提供原生事实，营销验证工作台、签名报价、绑定查询及暂停恢复。签收状态同步到营销 LC-02 权威进度 | 同一订单的商户、门店、SKU、活动和原生交易标识可串联。对照门店及故障路径验收完成。正式范围由运营签收后才标为已确认 |

第一项实施操作是在授权环境用具有目录权限的身份查询 `GET /v1/admin/merchants`、`GET /v1/admin/stores` 和 `GET /v1/catalog?storeId=…`。沿分页读取参与和对照店，从商城核实商户归属，从运营或 Auth 的权威记录核实组织范围，并保存脱敏证据。候选缺少实际源记录时标注待确认。

S2 明确配对后，S3 的来源补齐可与 S4 的独立身份准备并行。两者分别负责订单关系与机器授权。需要同改资金服务配置时，统一留到 S5 串行更新。S1、S2 优先使用既有隔离环境。首次需要启动候选应用或注入新隔离授权时，单独记录目标、配置版本和回收方式。生产上线仍走 LC-06。

## 2. 验收记录

| 用例 | 预期 | 验收证据 |
| --- | --- | --- |
| 参与门店及商品 | 同租户的启用商户、有效门店和已发布 SKU 在既有目录可读，返回实际版本 | 目录响应的脱敏摘要、来源和读取时间 |
| 同一订单 | 参与店指定 SKU 达到门槛。报价关联原生订单，绑定后可从运营入口查到对应申请 | 范围版本、商城订单或报价引用、原生订单、签名报价及绑定摘要 |
| 对照、错商品和错租户 | 同组织对照门店及非指定 SKU 无试点优惠。错租户、已冻结门店、下架 SKU 和伪造关联被拒绝或保持待核查 | 实际调用结果和授权检查，按既有错误契约记录 |
| 证据缺失及恢复 | 原生订单来源或回执暂缺时保留待核查。恢复后按原订单引用重查和绑定。同一关系重复请求幂等 | 补查前后状态、首次绑定回执和重复请求结果 |
| 范围变更与暂停 | 暂停后新订单退出试点。历史记录仍可按原版本、报价和账本核对 | 暂停前后各一单，保留授权撤销与历史处置记录 |
| 后续财务签收 | 单独验证同单实际支付、两次部分退款、逐笔出资分摊和日结 | 交易与财务的授权凭证索引，留在原有 LC-02 清单 |

候选制品按提交固定，真实获取的目录数据、隔离联调订单和正式同单凭证分别标明来源环境。若改动源码，相关仓执行受影响模块的真实持久化测试、既有契约回归及提交 CI。复用现有流程时保留实际查询、权限和联调证据。验收范围覆盖 S1 至 S6 涉及的变化，观察窗口和生产容量由 LC-06 约定。

## 3. 状态与恢复

- S1 本机目录和双店隔离技术验证已通过。真实商户、组织、两家门店和 SKU 仍待运营及 Commerce 在获授权环境确认。
- S2 完成当前源码及既有联调证据盘点。正式映射及目标环境的受信下单路径待核定。S3 至 S6 按上表依赖推进。证据见[核验记录](../../delivery/lc02-store-pilot/TEST_RESULT.md)。
- 本计划交付的是 LC-02 的范围准备。实施证据引用回填到 [营销 LC-02 进度](../../../../marketing-lowcode-platform/docs/delivery/lowcode-commercialization/PROGRESS.md)，财务凭证与观察期仍按原计划处理。
