# 首店满减试点实施方案

本版按运营负责人的视角确定首发范围、活动规则、出资预算、验收订单与停投条件。当前可以据此准备隔离联调。生产范围采用同一套条件，由实际商户授权、机器身份、真实支付与退款凭证完成原 [LC-02 签收](../../../../marketing-lowcode-platform/docs/delivery/lowcode-commercialization/READINESS.md#lc-02-试点签收单)。

## 1. 首发活动

| 项目 | 运营决定 |
| --- | --- |
| 活动 | 陶瓷随行杯单店满减，活动 ID 为 `lc02-mug-100-10`，首个范围版本为 `lc02-store-r1` |
| 商品 | 从本机 Commerce 的 `store-demo` 目录读取到已发布的 `sku-mug`，修订 1，单价 ¥59。以该价格和规格建立隔离验收商品 |
| 范围 | 同一商户、同一组织的两家店。参与店开启活动，对照店销售同款同价商品，保留原价。仅商城 WEB 结算入口参与 |
| 优惠 | 仅指定 SKU 的商品小计满 ¥100 减 ¥10，每订单减一次。运费、税费和其他 SKU 不计门槛。本活动订单只测试该满减，按 CNY 最小单位分结算 |
| 预算 | 平台单出资方承担全部补贴，独立 CNY 预算 `BUDGET:PLATFORM:lc02-mug-r1:CNY`，授权上限 ¥1,000。预留加未冲回的已确认金额受此上限约束。按既有账本规则，释放和成功冲回可恢复可用预算 |
| 窗口 | 首店正式放行日北京时间 10:00 起连续 7 天。预算占用达 ¥900 时运营复核并准备暂停，可用预算不足一笔优惠时停止承诺新优惠。暂停后核清在途订单和约定的退款观察期 |
| 发布 | 复用指定门店 SKU 满减工作台、审批与发布。版本、店铺和资金账户在提审及放行时复核。对照店始终列入验收，交易绑定机器只获得参与店的权限 |

两个起步场景分别是参与店买两件，商品小计 ¥118、实付 ¥108；对照店买两件同款，实付 ¥118。活动结束记录指定商品实付订单量、件数、净补贴、单均净补贴、退款及核账差异。对照店用于核对行为和观察成交变化；扩店结合商户的实际客流和毛利数据判断。

## 2. 已选定的联调范围

| 系统 | 隔离环境配置 |
| --- | --- |
| Commerce | 租户 `lc02-pilot`，商户 `lc02-merchant`，参与门店 `lc02-store-a`，对照门店 `lc02-store-b`。分别登记 `lc02-mug-a`、`lc02-mug-b`，两边同款同价。通过现有管理和目录 API 建立并复核记录 |
| Marketing | 租户 `lc02-pilot`，组织 `lc02-retail`，显式登记商城店铺到营销 `shopId` 的对应关系。活动和出资账户只挂 `lc02-store-a` 及 `lc02-mug-a`。对照店保留其独立商品 ID |
| Transaction Center | 单独的隔离租户、逻辑收款商户和隔离支付渠道。用已有初始化与管理接口取得真正落库的数值租户、商户、SKU ID，再关联到上面的商城范围。支付及退款通过真实服务接口承接隔离渠道回执 |
| Auth | 独立联调机器身份。商城结算服务向交易提供已核验的门店事实，交易绑定机器向营销访问其获准的租户、组织、参与门店和回执范围。幂等授权和撤销复用现有身份渠道 |

上述配置适用于专用验证环境。本机已读的 `store-demo` 作为选品和定价依据。正式参与店、对照店与渠道采用已授权的实际记录，并保留明确的跨系统映射。凭据与真实支付资料沿用受控渠道。

## 3. 交易与营销接线

当前交易报价先锁定应付，原生订单创建时使用数据库自增编号，现有营销绑定要求原始签名中带订单号。首期采用**带版本的交易报价引用**衔接这两个时间点。交易中心拥有报价到原生订单的持久关联。隔离试点使用新契约，现有按签名原生订单号绑定的路径继续适用。

1. **商城提供门店事实。** 商城 WEB 结算服务校验商户、门店、SKU、修订和范围版本。交易服务从受信服务身份取得这些信息。参与店匹配后进入活动报价，对照店保持标准报价。门店冻结、SKU 下架、授权或来源异常均保留可追踪原因。
2. **交易发起并锁定报价。** 交易在试点报价准备时持久化唯一的报价引用，绑定已核验门店与购物篮版本。营销在新版本声明中签入该引用、租户、组织、门店、商品摘要、有效期、活动版本和优惠分摊。交易核验签名和同一购物篮，写入冻结的原价、优惠、应付及逐行分值。远程报价调用在本地写事务外执行。商品版本变化或报价过期时提示重新报价。
3. **原生订单承接报价与预算。** 下单使用原有交易编号生成方式，在本地事务内持久化同一报价到唯一订单的关联。营销使用交易的受限证据查询核对报价引用、实际原生订单、门店、范围版本和原始签名摘要。试点优惠单需等资金预留成功再允许支付。预留超时先用原幂等键核对结果。明确预留失败时按既有取消或重新报价流程处理，并由买家确认新的应付。交易取消、过期和预留回执未知都有可恢复记录。
4. **回执到达后沿原事实结算。** 支付与退款以交易中心的原生订单、正常实收和成功退款为准。营销用已验证的报价关联绑定资金申请。LC-03 实施唯一支付确认，LC-04 按原分摊冲回。若退款只有金额且无法证明对应的订单项与件数，保留待核查。历史订单沿原报价和账本处理。

采用交易报价引用是本版技术决定。它在支付前锁定真实应付，并沿用交易中心的原生单号生成时点。S3 负责交易报价、订单关系与证据读口，S5 负责营销版本声明、预留和绑定校验。契约先定义权限、幂等键、请求摘要和兼容行为，再按各仓的既有迁移顺序落地。

## 4. 退款与验收数字

退款试验单买 3 件，各 ¥59，原价 ¥177，优惠 ¥10，实付 ¥167。优惠分摊按实际购买件数冻结到订单项。1000 分除以 3，稳定件序从小到大分配余数，得到 334、333、333 分，对应每件应退 5566、5567、5567 分。退款按订单项和实际退件数依次占用未退件位，成功后按该批冻结分值冲回，同一退款号只核销一次。

| 场景 | 交易应付或实付 | 买家实退 | 营销补贴 |
| --- | ---: | ---: | ---: |
| 参与店买 1 件 | ¥59 | — | ¥0 |
| 参与店买 2 件 | ¥108 | — | ¥10 |
| 对照店买 2 件 | ¥118 | — | ¥0 |
| 参与店买 3 件 | ¥167 | — | 确认 ¥10 |
| 第一次成功退 1 件 | ¥167 | ¥55.66 | 冲回 ¥3.34 |
| 第二次成功退 1 件 | ¥167 | ¥55.67 | 冲回 ¥3.33 |
| 两次退款完成后 | 净实收 ¥55.67 | 累计 ¥111.33 | 净补贴 ¥3.33 |

最后一件可在独立用例中验证全退归零。验收还覆盖非指定 SKU、错店、错租户、失效报价、错原生订单、重复与乱序回执、余额不足和暂停后重查。对照店使用独立 SKU 键，同时用相同规范商品的隔离契约用例单独验证门店拒绝，防止只验证到 SKU 筛选。日结按北京时间及实际入账日计算，退款跨日按自身入账时点冲减。

## 5. 执行和停投

1. **先准备专用环境与数据。** 沿现有 [S1 至 S6](IMPLEMENTATION_SLICES.md) 执行，把两店、同款商品、预算和真实落库标识固定在一版隔离配置。联调先拿参与店和对照店两单，验证报价及原生订单归属。
2. **再验资金和退款。** 跑三件试验单、两次部分退款及一次重放，核对实付、主账本、冲回和页面查询。确认支付前预留有效，预算扣减、释放、冲回均可复核。
3. **正式放行与回收。** LC-06 生产准入后开一个门店，至少复核一个完整关账周期。出现任一错店优惠、重复入账、超预算或大于 0 分的未解释差额时，立即暂停新试点。已承诺订单按原版本结算，保留配置与回执。完成核账和观察期后，由运营和财务依据记录决定扩店。

本版已经选定运营参数、隔离范围、接线方式和验收样本。正式环境的商户、门店、渠道身份和同单业务凭证仍由实际授权记录确认。
