# 交易中心 B 端第三轮体验设计

基线为第二轮已发布提交 `d5f700c`。沿用 React、Ant Design、现有主题、旧运营 Hash 路由和中央已发布导航。权限范围、接口形状和交易流程由项目原契约决定。

| 使用者与作业 | 体验决策 | 验收 |
| --- | --- | --- |
| 运营人员搜索并连续处理队列 | 统一宽表键盘浏览与位置恢复。接口失败、空结果和加载各有文字。中央与旧运营共享规则 | 有溢出才加入键盘停靠点，支持方向键与边界定位，普通表格及全屏共用横向位置 |
| 经营人员查看总览 | 已付订单卡联动同一日投影柱状图。同期日明细给出下单和已付比例，比例以同一 UTC 下单日为分母 | 数量轴使用整数。零分母保留空值。七日环比使用连续完整 UTC 日 |
| 商家和运营人员核对交易 | 完整订单详情进入时从标题开始，返回既有列表位置和触发焦点。窄屏主要单元格露出售后处理前置事实、支付类型和物流信息 | 原条件、游标、权限与动作均保留。以真实数据或对应契约验证 |
| 平台角色维护分类与核对日志 | 保留任务专用页面与原后端分页语义，套用共享表格反馈和键盘交互 | 完整类目集合支持真的总页数。日志使用已访问页 |
| 配置人员维护业务字典、权限范围和规则 | 沿用现有表单、弹层及动作，不增加配置页指标 | 入口、弹层、字段和结果在原验收套件回归 |

[既有 69 入口逐路由清单](../../delivery/b-console-product-experience/PAGE_CHECKLIST.md)作为本轮逐页基线，含旧运营 29、门店 1、平台 3、中央 36。列表交互共用表格，管理详情默认保持现有抽屉或弹层。需要深链和多组只读明细的订单继续采用独立详情。覆盖 320、390、1024、1440、1920 px 代表布局。开发预览连接已有本机接口进行只读验证，中央岗位与平台契约另验，完整交易写入走隔离 CI。

按业务边界落地公共表格、经营数据与交易路径、逐路由复核三个关联变更。[第二轮待补接口](../../delivery/b-console-experience-round-two/DATA_REQUIREMENTS.md)继续有效。缺少真实全量、比较窗口或阈值时登记需求。避免新增框架、依赖和接口。
