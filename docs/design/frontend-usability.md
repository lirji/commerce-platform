# 前端可读性与操作效率改造

## 已确认范围

用户确认全站前端优化及必要的后端只读查询补齐。以新版个人 Claude frontend-design SKILL 为标准；沿用 Ant Design、当前路由/权限、统一32px按钮及紧凑弹层。正常 Git main 发布、本机 Docker8602更新沿用已有授权。

## 连续实施切片

1. U1：共享查询状态、真实游标上一页/首页/下一页及位置说明；失败/加载期间禁止翻页，查询变化回首页，返回详情保留上下文。
2. U2：会员、商户、门店、商品及订单/履约/售后/退款核心经营列表补齐服务端关键字、状态和实际存在的时间筛选。保持租户/门店 SQL 权限与查询后重新授权；旧调用兼容，不新增写操作。
3. U3：运营与会员的全部页面检查，现有列表补充可用于决策的字段、中文状态/单位/说明，展示有效筛选条件。已有门店/会员/时间/任务类型筛选保留；复杂记录分页统一，既有专项权限客户端同步限定允许查询参数。
4. U4：列表密度、筛选栏和信息层级、详情空值及操作反馈；长表支持横向阅读，手机可用，按钮与弹窗不扩回旧尺寸。
5. U5：真实数据库过滤/权限回归、全站路由和交互回归、截图检查、编译与代码卫生；提交 main、精确 CI、更新本机 Docker 并核验资产/页面。

## 查询与分页契约

新增查询只进入 Owner API 与 Mapper 的绑定参数，筛选在 SQL LIMIT 前完成。关键词按实际业务编号/名称等明确字段搜索，不搜索私密地址或原始载荷。时间适用于真实已有时间字段，区间为起点包含、终点不包含；不得为无时间字段的列表伪造筛选。所有查询保留稳定 ID 游标和有界 limit。接口未提供总数时只展示本页数量和访问页位置，不伪造总页数；满页可尝试下一页，空末页可返回上一页。

## 验收

运营可通过直白标签查找跨页记录，在列表判断主体、归属、状态、金额/数量和时间；筛选与分页刷新/返回可恢复，条件改变不沿用旧游标。无权限、失败、未填写、零值与无数据分别表达。金额、业务写入、授权、幂等与请求未知结果保持现有边界。全部路由按实际消费者覆盖，代表页面和相关弹层截图人工复核。

实际查询能力和字段来源见 [只读查询补充契约](frontend-usability-queries.md)。U2可独立兼容旧前端；U1/U3/U4共用分页、筛选、样式和格式化实现，一起验证和交付。按钮统一32px；手机筛选按关键词/时间全宽、状态/容量并排呈现，宽表内部滚动，会员主要状态直接跟随名称显示。

2026-10-03用户反馈按钮过大和分页粘连后，尺寸统一调整为32px高、14px字、10px水平内边距、6px圆角。按钮配色在当前项目共享token中维护；个人Claude SKILL不再规定按钮颜色。分页数量、页码与导航分别参与flex间距，手机可换行，保留原游标协议及禁用条件。此前交付记录中的38px为当时已部署事实，不反向改写历史证据。
