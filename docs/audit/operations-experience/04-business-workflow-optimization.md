# 运营流程与跨模块协作

本次在同源的演示租户做了只读任务复现。一次步骤按可识别的主动操作计数，包括定位输入、提交搜索、打开详情、切换页面或确认操作。以下差值只用于比较明确的流程，等待、找到按钮所用时间、权限申请和业务处理时长另计。多个可用路径以写明的起点为准。

## 本机观察与目标路径

| 场景与起点 | 当前路径 | 目标路径和步数差 | 边界与验收 |
| --- | --- | --- | --- |
| 商品运营在默认 SKU 页查询一个无匹配名称 | 上方输入 → 查询。实际请求 SPU，6 条 SKU 仍在。再到下方输入 → 筛选商品，发送 SKU 查询并得到 0 条。共 4 步。 | SKU 页仅提供本页 SKU 搜索，从输入到提交共 2 步。该误用支路少 2 步，熟悉现有页的用户原本也可直接用 2 步。 | SPU 页签搜索结果订阅 SPU 请求，SKU 控件只作用规格，更改筛选清旧批选。 [组件](../../../frontend/src/features/ProductOperations.tsx#L107)。 |
| 交易运营已经取得订单编号，从订单队列核对支付 | 输入 → 查询 → 完整详情 → 查询支付 → 返回列表，共 5 步。实际命中 1 条，支付 GET 成功，返回恢复关键词与 URL。 | 有读取资格时进完整详情自动并行读支付摘要，人工核对动作仍独立。相同起点和终点 4 步，少 1 步。 | “无支付记录”“渠道未知”“已收款”各用权威事实，缺支付读权时保持原交易范围并显示状态。 [列表和返回](../../../frontend/src/features/Orders.tsx#L63)、[支付区](../../../frontend/src/features/Orders.tsx#L381)。 |
| 售后人员从申请列表读取原订单 | 当前申请 → 打开详情 → 记录订单号 → 切换订单列表 → 粘贴 → 查询 → 完整详情。后 5 步为依真实入口推演，本机实测已打开申请详情并关闭。 | 打开申请详情 → 已授权的“原订单”，之后支持返回原申请，按该路径最多减少 4 次主动操作。 | 链接携带精确不可混淆的原 ID，订单权限独立，切回申请保留原表格和上下文。 [旧申请动作](../../../frontend/src/features/AdminData.tsx#L438)、[中央售后详情配置](../../../frontend/src/iam/CentralAftersales.tsx#L49)。 |
| 营销人员从指定活动查该版预算 | 打开活动配置 → 读取活动号和版本 → 去预算 → 输入活动号 → 查询 → 在结果对比内容版。现状 6 步，其中打开、关闭详情本机复现，同版预算跨页为源码推演。 | 活动详情点“本版本预算”，2 步。少 4 步的条件是有两项读权限且目标版有效。 | 预算金额以固定内容版聚合，锁版本另显示，活动预览与预算预占分开。 [活动目录](../../../frontend/src/features/Marketing.tsx#L217)、[预算页](../../../frontend/src/iam/CentralCampaigns.tsx#L1032)。 |
| 中央财务从已展开订单摘要查原支付 | 当前在订单页取得编号 → 切支付页 → 输入 → 读取，源码路径 4 步。 | 兼具订单与支付读取权限时，点“查看支付”带入并 GET，变为 1 步。缺任一权限继续使用原独立入口。 | 保留按单授权及核对权限。支持“只有核对资格，无支付目录权”的合法岗位。 [中央订单](../../../frontend/src/iam/CentralOrders.tsx)、[中央支付](../../../frontend/src/iam/CentralPayments.tsx#L13)。 |
| 发券运营建立定向批次并排查失败 | 从人群与券目录取得固定版本 → 进定向发券 → 建批 → 读批次 → 查看逐人结果。实际本机批次目录为空，动作取源代码，未提交。 | 从已授权快照/券详情带一侧选项，校验另一资产和作用店，预检后建批，回执直接打开逐人结果。节省量待有合法数据和岗位实测。 | 明确目标范围、风险、有效期、冷却，停止和撤回任务方向不同。 [发券表单](../../../frontend/src/iam/CentralCouponDeliveries.tsx#L602)、[逐人表](../../../frontend/src/iam/CentralCouponDeliveries.tsx#L329)。 |
| 消费者店铺浏览并查看商品 | 选择商品打开详情，实际观察商品明细 GET，浏览触发的独立行为事件 POST 被验收工具拦截。 | 保留商品卡和详情，明确标价与最终报价，购物袋显示同店、优惠和抵扣口径。步骤仍为一次打开。 | 只读复现证明商品明细可查。真实行为数据、报价、下单、支付另用隔离集成验收。 [商品页](../../../frontend/src/features/Shop.tsx#L34)。 |

## 统一业务对象关联

| 出发对象 | 真实关联键 | 拟呈现的关联与做法 | 依赖 |
| --- | --- | --- | --- |
| 商家、门店、商品规格 | 租户、商家、门店、SPU、SKU、规格/价格版本 | 商家 → 门店，门店 → SKU/库存，SKU → 当前渠道价、计划、修订。每个页面标题显示真实查询作用域。 | 配置页、商品维护和授权商品目录沿用独立 Owner。库存与定价只读投影先于跨域展现。 |
| 订单及支付 | 原订单号、真实门店、付款渠道与原凭据、报价引用 | 订单详情顶部分订单状态、渠道状态、履约、售后。分区显示明细行、锁价、优惠出资、积分、权益，有授权才读取。 | 原交易确认强制使用原冻结资金语义。跨服务试点引用在业务不同对象间映射，保留已签发生时间和回执。 |
| 原售后、履约及退款 | 原订单、售后申请号、退款号、可信运单号 | 履约被拦时显示可读的原申请，售后情境直接跳当前申请的退款记录，财务按原退款核对。 | 一单可能存在不同申请或多次结果。聚合禁止仅按“最近发生的一条”推断对象。 |
| 活动、规则、人群与资金 | 活动号+内容版本，门店、预算号，规则版、人群快照版 | 活动详情出现固定资格与资产，预算以同一活动版本的上限、预占、已支出和余额呈现。预览标明观察时间与资格快照。 | 界面只读预检与提交端鉴权/状态变化分开，保留控制版本。 |
| 定向券、旅程和权益 | 批次号、固定快照、原券版，旅程号+固定版、实例、步骤，权益实例和原来源 | 从批次读逐人结果，从旅程读实际步骤与权益对象。截止、冷却、跳过等原因采用已知分类。 | 授权和存在性失败不暴露其他范围，已使用或过期券保留原状态，补偿责任由权益域承担。 |
| 停止任务、事件、重放 | 工作类型+原编号、消费者、事件编号、重放任务、回执 | 从业务问题定位可见事件，进入恢复审计或历史重放。试运行先显示事件范围和消费者允许的动作。 | 原因和证据脱敏。事件 TraceId 可辅助调查，始终用业务编号定位。 |

## 批量、复制和进度

- 商品定时计划以明确勾选的 SKU、预期版本和实际执行窗口为输入。提交前加选中数量、门店和变更前后摘要，提交后以计划明细核对执行、失败、取消。更改筛选或换店必须重新勾选。 [商品计划 UI](../../../frontend/src/features/CatalogScheduling.tsx#L71)、[商品计划接口](../../../commerce-app/src/main/java/com/lrj/commerce/app/http/catalog/job/CatalogSchedulingController.java)。
- 发券、动态人群、旅程推进和历史补齐按已有有界取批语义。受理后给原任务回执，显示实际处理、成功、保留、未处理，只有服务端允许时提供逐条恢复。避免由用户重复发起新批次代替原任务恢复。 [发券接口](../../../commerce-app/src/main/java/com/lrj/commerce/app/http/marketing/delivery/CouponDeliveryController.java)、[人群接口](../../../commerce-app/src/main/java/com/lrj/commerce/app/http/marketing/segment/SegmentController.java)、[旅程接口](../../../commerce-app/src/main/java/com/lrj/commerce/app/http/marketing/journey/JourneyController.java)。
- 活动、旅程和低代码配置复制属于候选增强。复制成独立新草稿，重校门店、权限、固定资产与有效窗。老审核结果、预算以及任务执行引用不进入新草稿，先用当前创建用例证明可覆盖。 [活动草稿](../../../frontend/src/iam/CampaignDraftForm.tsx)、[运营页面](../../../frontend/src/iam/CentralOpsPages.tsx)。
- 售后审批、订单支付核对、多会员调整均保留逐对象业务校验。岗位确认确有高频批量需求后，再核定对象资格、资金和审核边界。 [风险清单](05-operation-risk-audit.md)。
