## 依赖关系

`实际作用范围与鉴权` → `正确筛选和原对象定位` → `权威只读摘要/聚合` → `跨页下钻、持久结果` → `跨域待办、批量治理、可复用导出`。

每批发布需对应页面、契约和可复现任务，用相同起点记录主动步骤或查询结果。技术与业务验收分开报告。P0 候选完成隔离复核后更新优先级，P1 上线顺序优先采用与用户日常作业重合的场景。沿用现有 MyBatis-Plus/Mapper XML、Flyway 和状态契约，必要迁移先确认索引、历史兼容、回退与并存，具体排期和负责人由项目负责人确认。

## 待决事项

- **业务**　核心队列优先级、异常阈值、审批职责、主要运营时区和日期口径。需要店长、营销、财务、售后及平台岗位分别给至少一条实际任务。
- **技术**　中央可用的角色与多门店测试矩阵，订单可供独立门店筛选的权限语义，复合游标在启用多活动时的兼容条件与真实性能数据。
- **治理**　受限导出的岗位、审批、脱敏与留存，正式渠道验收环境及数据源授权。先确认方案再开任何开发任务。
