# 日常经营与会员营销使用手册

本轮在原统一电商上增加经营能力，继续使用同一个应用与数据库。没有引入 Drools；规则编辑器生成受限类型 AST，实际判断只读取服务端会员、商品和订单事实。运营可以重复创建新配置版本，预览、审批、发布和观察结果。

## 建议的第一轮运营

1. 平台管理员在「会员档案」维护资料或冻结/恢复会员，注销为不可恢复的服务终态，保留交易和审计。不是物理抹除数据。
2. 在「经营授权」把商品经营权授给已存在的 OPERATOR 主体，选择具体门店或商家。商家授权覆盖其正常门店（包括未来新店），不授予会员、资金或营销全局管理权限。撤销后后续 API 请求即时重新查库，旧登录会话也不能继续经营。
3. 在「商品管理」建立 SPU，再以属性=值建立 SKU 规格。新 SKU 初始下架，填写原因、价格后上架。调价与上下架保留修订；历史有效报价和订单继续沿原快照，不被覆盖。紧急禁售并不自动取消既有报价。
4. 在「会员成长 → 成长与等级规则」发布未来或即时生效的成长率和等级门槛。完成订单按下单时已生效的策略奖励，退款沿原成长率冲回。人工调整必须填写原因。发布等级门槛不会立即改写全库，成长变化或显式重算才更新等级。
5. 在「会员标签字典」创建标签，在成长页查询会员并分配/撤销标签。标签不是客户端可自报的优惠资格。
6. 在「动态人群」配置成长、净消费、状态、等级、标签规则。先手工刷新，检查扫描/命中、有效期和完整快照，再启用周期刷新。任务失败保留检查点，最多重试五次后隔离；取消不发布半成品。
7. 在「活动管理」配置商品包含/排除范围及阶梯优惠，可选择版本化人群/规则。输入真实会员和 SKU 做只读预览；预览不占预算和库存。复制新版本后审批发布，旧配置不可原位修改。人群刷新不会偷偷替换已发布活动所绑定的快照。
8. 在「营销旅程」选择注册、等级变化、人群新入组、支付或手工触发，设置入组规则和通知频控，连接等待/判断/权益/通知/结束节点。新会员触发必须有频控；发布前事实不追溯触发。暂停停止新入组，已有实例可单独取消；已发送通知/发放权益不因取消自动撤销。
9. 在「营销效果」按门店、日期查看活动版本的成交、成功退款和承担金额，再用「旅程执行」核对触达与抑制。历史订单通过「补齐历史订单」每批100单重建，保存游标可继续，重复执行安全。

## 规则和金额口径

- 成长是会员等级指标，不是可提现/兑换积分钱包。退款可能造成负成长，等级按非负部分判断，不丢弃需要冲回的债务。
- 商品范围内金额达到最高满足阶梯时计算优惠；排除优先。百分比按基点（1000 = 10%），受该档和活动总上限限制。仍单活动择优，券按既有可叠加规则执行。
- 人群为刷新区间视图；每批读取当时事实，不宣称全库同一时刻快照。仅完整且未过期版本可命中。
- 旅程频控为每租户、会员、旅程跨版本共享的 UTC 固定时间桶，不是滑动窗口。改窗口长度会重新确定桶；重复事件不重复计数。
- 活动报表按下单时间选订单，包含这些订单截至投影更新时的所有成功退款，退款可以发生在查询日期之外。
- 「净收入」仅成交实付减成功退款。平台/商家承担沿原成交快照（包括可叠加优惠券），不自动恢复预算。不含商品成本、支付费、渠道费，不是利润或因果 ROI。
- 旅程面板跨版本汇总新增执行事实；升级前的执行不追溯补计，不能当作销售归因。

## 可重复演示与浏览器验收

运行新版应用后执行（本地 API、授权的项目 schema）：

```sh
COMMERCE_E2E_BASE_URL=http://127.0.0.1:8603 \
COMMERCE_E2E_SCHEMA=commerce_test_20260923 python3 scripts/seed-operations.py
```

首次创建隔离经营租户，真实 API 写入品牌/两门店、限定门店运营授权、会员、成长策略、标签、SPU/SKU/库存、人群定义、阶梯活动和升级旅程。私密 `.local/operations-access.json` 内含 adminToken/memberToken/operatorToken 和目标环境（文件0600，不入Git）。凭据有效期一天，重跑延长本夹具凭据有效期。

重复执行回放同批幂等命令，不重复创建业务数据，也不覆盖运营后续手工更改。配置有效期保留初次的时间；需要新一轮时显式加 `--fresh` 创建全新租户，不清空旧数据。不要以 seed 重跑刷新已经过期的活动，也不要无界创建演示租户。

浏览器测试每次先生成两套独立租户，避免新成长/活动影响旧交易回归价格：

```sh
export COMMERCE_E2E_BASE_URL=http://127.0.0.1:8603
export COMMERCE_E2E_SCHEMA=commerce_test_20260923
python3 scripts/prepare-e2e.py
python3 scripts/seed-operations.py --fresh
COMMERCE_UI_URL=http://127.0.0.1:8603 \
COMMERCE_EVIDENCE_DIR=../.local/operations-evidence npm run e2e --prefix frontend
```

测试包含沙箱收款/退款操作，需要显式开启 sandbox。通常开启原有 workers；本机已有大量故障注入测试租户时，可仅对本次两租户调用管理端事件/旅程 pump，防止推进无关测试事件。CI 使用独立临时库和原有自动 worker。

## 发布与故障处理

V16–V22 是追加迁移；已应用迁移不可编辑，修正必须追加。新角色/状态/事件意味着不能直接回退旧应用就宣称兼容：特别是 OPERATOR、CLOSED、会员触发事件和新旅程配置。停止新配置发布/暂停活动与旅程后，先核对读写与消息兼容，再决定应用回退；退款、成长冲正等已提交效果需业务补偿。

不增加公共中间件，复用 dev_infra MySQL。批次限额可证明有界执行，但未做生产容量或灾备承诺。首次上线分析投影需要分批补齐历史；积压/失败在事件、人群任务与旅程实例中检查并有界重试。真实 IdP、支付、短信/微信、外部权益和 WMS 仍是后续集成范围。
