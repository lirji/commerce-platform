# 会员经营与营销闭环改造计划

目标：共享能力中台服务品牌自营商城，并保留多项目复用边界。用户已授权先出计划再连续实施；本计划记录该授权，不再次要求逐切片确认。基线 fb7adf6。原工作区两处用户改动保留，实施工作区为 commerce-platform-operations，分支 feat/member-commerce-operations。

## 建设范围与验收

1. 日常经营：会员资料、冻结/恢复/注销；商品规格、上下架、调价与历史版本；商家/门店操作授权与撤销。
2. 会员经营：可配置成长与等级、可审计成长账本、退款冲回、标签与动态人群快照。
3. 精细营销：商品范围、分档优惠、受限可信会员事实、规则预览、版本化活动复用；沿用预算、券和权益资金约束。
4. 旅程：扩展会员事件触发和运营频控，复用持久检查点与效果幂等；运营可运行、暂停、观察和调整新版本。
5. 效果：活动版本维度的成交、退款、净收入、营销承担额，明确金额口径与观察窗口；不得把销售额/补贴比称作利润或因果 ROI。
6. 所有能力均有真实数据库/API与管理界面；关键行为用真实 MySQL 集成测试和浏览器验证。旧交易和订单快照须兼容。

## 范围边界

本轮不接真实支付/短信/微信/外部 IdP，不做全套 CDP、付费积分清结算、商家结算、WMS、统计显著性实验平台或任意代码规则。现有沙箱渠道继续可用。新规则只读可信事实，运营配置不能执行 SQL/脚本。注销为终止服务状态，保留订单和审计；法定保留/物理擦除另需业务依据。

## 技术路线

保留 Java 21、Spring Boot、MyBatis XML、MySQL、React/Ant Design、模块化单体。扩展受限 AST、不可变配置版本和领域策略，复用 Commands、Outbox/Inbox、持久旅程；暂无需要引入 Drools、Kafka 或第二套任务平台的证据。批量人群刷新分批/检查点执行，旧快照在完整新版本可用前继续使用。

## 实施顺序

详见 ../../design/member-commerce-operations/IMPLEMENTATION_SLICES.md。OP01–OP03 完成日常经营；OP04–OP07 完成营销闭环；OP08 全链路验收和交付。每个切片包括后端、迁移、前端、验证及文档；不在最后集中补全部 UI。

## 发布与回退

只追加 V16 及以后迁移，V1–V15 不变。新配置默认未启用，已有会员等级与旧 SKU 继续可用。数据库迁移和新状态不能用回退镜像冒充业务补偿。必要验证失败不推 main。正常逻辑提交、验证后快进/合并远程 main 并检查 CI；不部署生产，不改当前 8602 容器。原主工作区有用户未提交变更，交付不得覆盖它。

## 验证门禁

增量真实 MySQL 测试覆盖权限、非法状态、版本冲突、重复请求、退款/重复事件、资金口径和规则边界；前端类型/构建与浏览器操作覆盖新页面；最终完整 Maven、前端与远程 CI。历史 145/4 测试结果不作为本轮证据。测试仅 commerce_test_20260923，运行生产数据与共享基础设施禁止清空。
