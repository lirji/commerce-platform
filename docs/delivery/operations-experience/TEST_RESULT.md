# 首批运营体验改造验证

验证范围为 [S1–S5](../../design/operations-experience/IMPLEMENTATION_SLICES.md)，源码基线 `a5f1b37`。证据存放在本机忽略目录 `.local/operations-experience-delivery/`，日志和截图不包含交付凭据。

| 切片 | 验收结果 | 证据 |
| --- | --- | --- |
| S1 中央组织入口 | 精确的 `GET /operations` 返回静态页面壳。匿名 POST、未注册页面、导航与商品 API 保持拒绝。浏览器使用符合公开契约的本人菜单夹具，组织入口跳到唯一获准的运营页面。 | `AuthorizationCoverageTest.centralPagesServeOnlyStaticGetShell`；`central-workspace.spec.ts` |
| S2 中央运营页面筛选 | 关键词、草稿状态、每页 100 条经原客户端发送。首批正确接收 100 条，下一批从实际尾项开始，刷新保留条件和游标，重置回默认首批。既有 Owner 的实际 GET 再核对关键词、状态和无匹配条件。 | `central-workspace.spec.ts`；`ops-owner-preview.json` |
| S3 商家与门店目录 | 商家和门店各自保留条件，切换、刷新和重置互不覆盖。旧共享参数只迁移至书签指定页签。 | `central-workspace.spec.ts` |
| S4 SKU 与 SPU | 1440px 的 SKU 页只有规格筛选。切到 SPU 可见商品资料筛选。两次实读分别请求各自端点（HTTP 200），无匹配时两表各自为空。切回 SKU 保留原条件，390px 页面可用。 | `live-read.json`；`sku-1440.png`、`spu-390.png` |
| S5 订单范围与窄屏筛选 | 订单入口明确权限内各店或本人范围，保留订单实际店铺编号。窄屏折叠日期和页大小，展开后日期条件实际进入请求，折叠、刷新仍可用标签清除。详情返回保留列表焦点与条件，390/320px 无文档级横滚。 | `interaction-refresh.spec.ts`；`live-read.json`；`order-390.png`、`order-320.png` |

中央浏览器验证使用已声明的只读 DTO 夹具。真实企业登录、岗位授权、生产渠道和业务写入留给相应环境验证。前端实读使用现成演示租户，验证进程拦截写请求。Java 验证使用自有隔离 MySQL，Flyway 与店铺、资金和权限测试执行在该实例。新 SKU、订单和中央目录截图已经查看。

首次窄 Maven 验证因仓库不允许上游模块零测试而终止。全量尝试先后纠正了本机全局 SDK 与仓库固定版本不匹配，以及隔离库未提供测试专用地址密钥。开发模式下，原基线和改造版都复现了旧页面编排组件默认值缺失，原基线打包版通过，最终打包版本通过该项及全部相关浏览器回归。格式化工具自动探测没有找到统一入口，变更过的前端文件以仓库 Prettier 实际检查为准。

## 汇总

- Maven 全量 `clean verify`，78 套件共 562 项，557 通过，5 条按既有条件跳过，0 失败或错误。
- 默认及中央 UI 正式构建成功。最终打包浏览器 24 项全通过，覆盖中央本人导航、目录回显、100 条分页、订单和共享交互。中央 36 路由的宽屏、390px 与 320px 已浏览器检查。
- 既有沙箱运行服务 8602 维持审计时的部署版本。临时预览仅用于验收本轮前端，隔离库仅用于此轮验证。
