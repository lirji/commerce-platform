# 经营数据口径与后端待补能力

## 本轮经营总览

- 继续读取 `GET /v1/admin/dashboard?storeId=…`。已付趋势使用 `daily[].paidOrders`，日明细与图表使用同一组 7、14 或 30 日记录。
- 已付比例来自同一 UTC 下单日的 `daily[].paidOrders / daily[].orders`。没有有效分母或约束不满足时留空。数据覆盖后端已消费或重建的订单投影，页面记录窗口与读取时间。
- 已付订单的七日环比使用响应中最近两个连续完整 UTC 日区间，每组七日。金额沿用精确十进制口径，订单使用整数。当前日部分数据仍可在趋势中查看。

## 待补能力

| 场景 | 需要返回或正式定义的数据 | 口径与验收 |
| --- | --- | --- |
| 游标列表完整分页 | `totalCount`、`hasMore`、受支持的页定位方式、`asOf` 或快照令牌 | 同一过滤条件及授权范围。并发新增、删除、撤权、过期后仍能解释结果并恢复 |
| 订单、售后、商品、店铺、活动、权益状态快筛 | `statusCounts[]`、`countScope`、`asOf`。异常队列另需 `oldestPendingAt` 和 SLA 阈值 | 聚合口径与点击后的明细一致。失败和真实零值可区分，不分页求和代替全量 |
| 经营同比、跨店比较及真实支付漏斗 | 授权门店组、当前和同期时间窗、适用经营日时区、`coverage`、事件水位和阶段去重计数 | 说明部分时段、投影延迟、闭店/新开门店及同期空值。支付阶段统计按同一批订单比较 |
| 库存预警、营销预算与时效 | 每门店 SKU 阈值及来源、活动版本与预算关联、实际结束策略与阈值 | 现有零可售、已占用、活动截止事实可继续展示。低库存和预算风险由可信配置定义 |
| 券与权益完成率 | 冻结目标数、去重后已处理数、发放与失败分类、完结时间及授权补偿待办总数 | 同批次和固定来源。目标完成率与已处理记录中的实际发放比例分别展示 |

保留[首轮接口细节](../b-console-product-experience/DATA_REQUIREMENTS.md)及[第二轮真实用数记录](../b-console-experience-round-two/DATA_REQUIREMENTS.md)。本轮交付范围为前端。
