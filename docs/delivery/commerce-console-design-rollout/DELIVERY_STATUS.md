# 交易中心设计推广

用户确认工作台采用数据驱动布局、订单采用高密度运营布局、商家商品采用现代简约布局。任务分支 `feat/commerce-console-design-rollout`，基线 `daef5ff`，产品提交 `4be9d87`。入场工作树干净。推广验证后沿用本机 Docker `127.0.0.1:8602`。

## 已应用布局

| 页面族 | 任务布局 |
| --- | --- |
| 经营分析和平台健康 | 数据驱动总览直接生效。指标、时间范围和趋势集中，支付退款对比和逐日明细保留操作。营销效果和运行健康的口径靠近对应指标。 |
| 交易和后台作业 | 默认紧凑行距，浏览器中已保存的行距优先。订单、履约、售后、退款的快捷状态走原服务端条件，清除或切换后回首批。中央订单和支付先读结果，独立动作位于相应列表或记录后。 |
| 商家、商品和名录 | 商家只显示原授权范围。运营和中央商品共享简约布局，销售状态和关键词复用原查询。商品、会员、店铺、授权主体及其他目录的名称和业务编号按字段呈现。 |
| 活动、旅程和配置 | 活动与动态规则、旅程、人群、运营页的名称和编号单独呈现。中央活动表单沿用契约分区并定位无效字段。完整订单、交易明细、回执及校验沿用原有详情和写入流程。 |

工作台和旧运营订单继续支持比较链接。普通入口打开默认布局，退出比较保留原筛选、游标、门店与趋势窗口。会员入口沿用其原视图。

## 验收

- 29 个旧运营入口以真实 API 在 1440、1920、2560、1024、390、320 px 核对，共 174 个布局。商家及三个平台入口共 24 个非重复布局，均以真实账户读取。运营真实会话也核对两个默认方向、比较的打开与退出。商家跨店铺读取仍为 403。
- 中央 36 个授权或协作入口在同六个宽度核对，共 216 个布局。中央登录使用现有独立的响应契约环境，真实 IdP 交换和真实授权核验沿用其独立环境。中央 26 个现有 Playwright 用例通过。
- 重点回归 23 项通过，另复验两个已批准默认入口；TypeScript、Vite 构建、菜单契约 4 项与差异检查通过。视觉矩阵业务写入为零。
- 视觉复核确认 1440 px 的交易状态、编号与操作清晰可读，2560 px 的活动页保持主操作和数据表对齐。订单比较入口在首轮默认切换中失去，后经修复和回归恢复。共享队列按钮具有独立的操作热区，普通按钮沿用统一尺寸。
- 证据在 `.local/commerce-console-design-rollout/`，包括前后页面、中央契约、真实角色、回归日志和 `visual-review.html`。

采用个人架构规范中的业务建模、接口契约、安全与验证、发布治理。GitHub Actions 和本机 Docker 的精确版本与最终状态在同目录内的交付与部署回执核对。
