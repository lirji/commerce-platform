# 会员与商品经营手册

本轮接续日常经营基础，定位为可复用业务能力与品牌商城。功能基于同租户、门店权限及明确领域API；仍为模块化单体，并未把复用等同于拆微服务。

## 从工作台开始

管理员进入「经营总览」，查看租户会员分布、本店在售规格、近30个UTC自然日已付订单、实收/成功退款/净收。可切换图形和每日数据；搜索框可直接进入全部功能。手机使用抽屉导航。会员仍从商城进入购物、订单、券、权益和成长。

数字来自真实数据库聚合。会员总量属于租户，商品与成交属于当前门店；成交依赖事件消费或重建。下单日期选队列，窗口外成功退款扣回原订单日。各域读取不构成同一强一致快照。成交优惠保留原承担，不等于退款返预算；净收不含货品/渠道成本，不能当利润或因果ROI。

## 会员经营顺序

1. **会员成长 → 周期等级**：发布生效时间、1–366天周期、递增等级门槛。没有周期策略的租户保持原成长规则；启用后由周期考核管理等级。上一周期净成长可用于保级，退款按原订单发生日修正，累计成长和周期成长分开展示。
2. **周期权益**：创建权益定义并绑定策略版本/等级。按会员、周期与权益来源唯一发放，后台重试不重复到账。受理和可用不同；会员钱包可以核对真实结果。
3. **积分策略与账本**：配置净支付赚分比例、有效期、订单抵扣开关、每元所需积分和最高抵扣比例。订单完成赚分；取消释放冻结；部分退款按原行分配返还，过期部分不延寿；已消费奖励被退款追缴时形成债务，后续收入先偿还。管理员调整须版本和原因。
4. **积分兑换**：配置积分兑换目录、固定券/权益版本、价格、总配额、单会员上限和有效窗。兑换采用原子扣分与发放；额度不足整体回滚。兑换券采用受控来源，不开放普通领券入口。会员可查看兑换记录与到账钱包。
5. **画像与行为**：会员或有权运营维护生日（MM-DD）和旅程开关。商城浏览/加购写真实事件；服务端定时及身份校验、去重和每日有界接收。动态人群可用30天行为、最近成交等事实生成固定版本快照。
6. **定向发券**：选择受控券版本与固定人群快照，设置截止、会员频控。发放记录包含发出、跳过和错误原因；5次失败隔离后可恢复。取消只停止新发放，撤销仅收回未使用券；已用、占用、过期券会保留并说明原因，相对有效期固定在钱包实例。
7. **生命周期旅程**：在生日、沉睡、复购、加购未成交模板上配置时间阈值、圈选/频控、等待、条件、发券/权益、通知和结束。发布后扫描保存检查点，按节点与来源幂等执行。禁用旅程偏好会停止未执行效果；生日按UTC且2月29日仅闰年匹配。加购排除基于本店加购后创建的已付订单，不推断更早下单后才付款的行为。
8. **效果比较**：活动按成交版本、旅程按首次入组版本/会员及观察窗、定向券按实际钱包券归属。展示观察是否成熟、实收退款净收及优惠承担。旅程同一订单可能出现在不同版本行，不能跨行相加或宣称因果提升。旧投影可使用有界重建，未处理事件仍会产生延迟。

## 商品经营顺序

1. 在「商品管理 → 类目与模板」维护最多三级类目、不可变版本规格模板。创建SPU后，在首次创建SKU前绑定模板；后续SKU必须完整使用模板允许值。已有自由规格不强制迁移，也不允许直接换模板破坏既有组合。
2. 展示资料支持详情、最多6张图片URL、类目；支持受限包内 `/media/` 路径或HTTPS图片，无上传存储服务。条码是门店内唯一经营标识，与价格版本独立，不代表GS1认证。
3. 经营搜索可看上下架；商城仅可售商品，支持名称/条码、类目和当前渠道价区间。使用关系库有界游标，不承诺海量全文检索性能。
4. 选中SKU创建批量上架、下架或逐项调价。预期版本固定，定时最多未来30天，截止在开始后7天内。版本冲突跳过并保留回执；每项效果/历史/审计/游标原子提交。取消不撤销已调价，恢复只继续未完成项。原运营身份或门店授权失效后不能继续写商品。
5. 渠道价支持WEB/MINI_APP、独立版本与有效期。渠道从受控凭据取得，没有会员自行切换低价渠道接口。有效期外/禁用回退基础价，经营搜索显示基础价。报价固化渠道价版本与期限，改价不重写旧报价；跨渠道不能消费同一报价。

## 本地演示与验证

私密文件在本工作区 `.local/`，不打印令牌、不入Git：`member-suite-access.json` 的 `adminToken` 为运营、`memberToken` 为周期权益会员、`checkoutToken` 为积分购物、`exchangeToken` 为兑换、`behaviorToken` 为画像、`deliveryToken` 为定向券、`journeyToken` 为生日旅程。`dashboardToken` 专供总览真实交易种子。此前 `demo-access.json` 与 `operations-access.json` 仍有各自隔离租户，不能混用租户数据。

```sh
# 本地Docker新版运行后（项目库commerce_local）
COMMERCE_E2E_BASE_URL=http://127.0.0.1:8602 python3 scripts/seed-member-suite.py --fresh
# 8604隔离测试实例明确选择测试库
COMMERCE_E2E_BASE_URL=http://127.0.0.1:8604 COMMERCE_E2E_SCHEMA=commerce_test_20260923 python3 scripts/seed-member-suite.py --fresh
```

`--fresh`建立新租户，不清数据；不带参数回放同一组命令。种子有效期固定在首次创建时间，需要新有效窗时创建新夹具，不覆盖已有运营修改。种子通过真实API创建等级/权益/积分/兑换商品、类目、模板、图片条码，并完成两笔沙箱收款及一笔退款来产生可核对总览。仅认证令牌摘要由受控种子直写凭据表。

`commerce.workers-enabled=true`自动推进。关闭时可以通过对应页面的考核/过期/推进按钮与管理员事件pump有界推动，健康状态不代表任务完成。测试库会保留历史测试租户，后台一轮有预算，不能假定第一轮覆盖全部租户。

## 升级与回退边界

本轮V23–V34全部追加迁移，不修改已应用历史，不加新中间件。升级先完成所有写入器/worker，再启用周期、积分、模板、旅程新节点、经营任务或MINI_APP身份。旧程序不能完整理解积分/渠道/新旅程快照，不可混跑新功能流量。

业务效果不能靠镜像回退撤销。故障先停止新的经营入口/后台任务并核对回执，修复后从持久检查点恢复；已成交、发券/权益、调价需各自补偿。保留地址加密密钥和数据库，不做清库或Flyway clean。此轮只交付本地Docker，不含生产发布、真实支付/外部权益/WMS/IdP认证或容量灾备承诺。
