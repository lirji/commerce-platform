## 浏览器验收

| 检查 | 结果与证据 |
| --- | --- |
| 基线 | 用同一套真实 API 和账户拍摄六个代表页面。1440、1920、2560 px 共 18 张，位于 `.local/commerce-console-design-pilot/before/`。 |
| 响应式 | 六种比较布局及商品、订单完整详情、营销配置和商家商品经营，共 10 个视图。每个检查 1440、1920、2560、1024、390、320 px，共 60 个通过。页面宽度适配，长表在容器内滚动，活动保存操作在可见范围。证据为 `after/` 与 `visual-result.json`。 |
| 工作台 | 7 天切换、图表左右键、明细表、切换设计时保留窗口及真实队列跳转通过。另用仓库既有隔离种子生成的真实成交及退款，核对投影与界面金额并保存对照图。 |
| 订单 | 快捷队列发送服务端状态条件，日期下拉、精确搜索、详情浮层、进入及返回完整详情均通过。返回恢复原焦点和查询。末页按钮正确禁用，三页游标切换、切换设计保留第三页、快捷队列回首批通过独立响应契约测试。 |
| 商品和商家 | 授权店铺来自真实接口，访问未授权门店返回 403。销售状态和关键词一起发给服务端，渠道价菜单和调价弹层可读、可关闭。规格名称和编号独立分列，保留编号复制和批选。 |
| 营销与复杂详情 | 四分区导航、字段验证定位、保留活动草稿输入、放弃修改及入口焦点恢复通过。订单通过真实接口打开支付核对。 |
| 回归 | Vite 生产构建、菜单契约 4 项、重点 Playwright 23 项、中央响应契约 21 项及订单预览游标复验通过。浏览器视觉走查中，未发生业务写入、意外失败读取或页面异常。 |

首轮视觉对照将 Tabler 和 Refine 的指标到趋势路径、Shadcn Admin 的低重量行操作和 Saleor 的明细分区放在同一评审中。随后调整了订单操作列、商家筛选和主操作对齐、活动配置焦点，以及完整详情的付款区。最终版本再次拍摄。对照页 `.local/commerce-console-design-pilot/visual-review.html` 可切换三个桌面截图宽度并打开原尺寸。脚本与日志都保存在该目录。
