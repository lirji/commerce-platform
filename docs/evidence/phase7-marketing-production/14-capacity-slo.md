# 容量与运维指标

本地专用库、8 并发、每层 120 次真实报价全部成功；具体 P50/P95/P99 和 JDBC 分段见 `02-performance-decomposition.md`。这只是测试机在该数据层与短时间流量的**实测容量**。实际 quote 的数据库事实准备占主导；同活动额度争用首先暴露预算行/券定义行锁串行瓶颈（P95 305/388 ms）；无法换算为生产承诺。候选上限 100、固定人群 500、应用连接池 8、Tomcat 64 线程是当前明确边界，下一轮要按真实峰值与租户分布验算。

## 运行指标

- 报价请求成功率与延迟分位；按环境和阶段汇总，禁止把 campaign/member/order ID 当指标标签。
- 当前有效候选数、超过 100 的拒绝数、报价决策/数据库延迟。
- 券 `reserved+issued<=quota`、HELD 超出订单付款窗的数量、券发放冲突和支付事件重试/隔离。
- `platform_event` 待处理、最长待处理年龄、无路由、隔离与近期完成延迟；用原运行时监控，不再造失败队列。

客户 SLA/告警阈值没有业务目标，暂不臆造。操作警戒：超过 100 有效候选立即阻止新发布并排查活动有效期/店铺选择；任何额度约束违例是数据正确性事故；到期订单仍保留 HELD、事件积压持续增长时由值班人员调查。其余延迟阈值需要压测和实际流量基线后设定。

## 运行手册

| 症状 | 诊断 | 安全操作 | 升级条件 |
| --- | --- | --- | --- |
| 活动不命中/误命中 | 预览 Trace、固定版本、人群水位、规则事实、活动时间 | 复核快照/发布时间；暂停或发布新版本 | 已成交受影响须业务补偿 |
| 候选过多 | 同租户店铺当前有效发布数、候选索引计划 | 暂停过期或错误配置活动，不抬上限 | 超过 100 仍持续拒绝 |
| 券额度不足 | 定义 `issued,reserved,quota`、订单 hold 状态 | 检查预留与订单状态，按合法取消/完成流转 | 约束违例或长期孤儿 HELD |
| CREDIT grant 卡住 | 执行详情的 grant/事件引用，运行时隔离分类 | 按原恢复 API 的受控重试；查权威台账 | 不明结果或重复效果风险 |
| 发布拒绝 | 审批版本、规则、人群新鲜度、券开关/受控定义 | 修新版本或等全量升级，不绕过校验 | 活动时窗内无法修复 |
| 混合版本异常 | 节点 commit、Flyway 版本、事件 PENDING/unrouted | 保持券开关关闭；让 NEW 消费积压，核对 OLD 全退 | 新事件无 NEW 消费者或报价对旧节点失败 |
| 执行积压 | 事件待处理年龄、隔离数、订单/券状态 | 限定租户/事件范围恢复，观察 Inbox 和 grant | 持续扩大或权益错发 |

## 容量结论与边界

| 负载 | 已测本地范围 | 结果/界限 |
| --- | --- | --- |
| 历史活动 | 每租户 4,000 行，80 当前有效 | 新索引仅读 80，仍拒绝 >100 同时有效候选 |
| 固定名单 | 产品 100/500；存储探针 50,000 | 主键单点查询可接受；公开上限不提高 |
| 历史操作 | 执行、grant、event/Inbox 各 50,000 | 实际游标小页和主键查找有界 |
| Quote | 8 并发/层；三租户 12 并发 | 全部成功，后者约 228 请求/s |
| 同活动争用 | 双进程、每提供者 120 用户、12 并发 | 30 成功/90 额度冲突，最终额度正确，约 95 下单请求/s（含拒绝） |
| 支付赠券 | 30 个真实付款事务/双节点 | 内部发券 P95 19.548 ms，核对 HTTP P95 51.85 ms |

没有长时间 soak、硬件隔离、生产流量或获批容量预算；以上不足以推导生产承诺。将客户 SLO、保留期与资源预算作为下一阶段输入；依据本机批次不能承诺 p99。监控复用现有 worker/event 指标、业务计数与可关闭日志；无高基数标签、新调度器或中间件。

保留/清理：本轮不执行历史删除。新 V43 hold 与钱包来源、历史执行固定版本必须一并保留解释链；不能用 TTL 删除 HELD 或把清理当取消。现有恢复/回放清理规则不得早于可重试窗口；实际保留期仍由业务治理，未虚构统一期限。
