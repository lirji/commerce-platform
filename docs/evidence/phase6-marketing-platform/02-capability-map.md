# Phase 6 能力图与差距

```text
固定人群快照 / 规则资产 / 内部 CREDIT 权益定义
                    ↓
活动不可变版本 ──审批──发布──单活动有效版本
                    ↓
可信会员、商品与报价事实 → 纯 Java 规则/优惠决定 → 报价版本快照
                                                   ↓
订单消费报价 → 预算与权益原子预占 → 支付事件 → 幂等权益发放
                                                   ↓
                         [缺口] 持久营销执行记录、履约结果与失败证据关联
```

| 目标能力 | 已有证据 | Phase 6 增量 |
| --- | --- | --- |
| 规则决定 | `marketing` 纯计算与有界 AST | 稳定执行摘要、原因和第二规则变体证据 |
| 版本发布 | `marketing_campaign`、规则资产、人群固定版本；单活动发布唯一键 | 完整绑定校验、并发与回退历史测试 |
| 受众资格 | 固定快照与动态任务生成快照 | 本切片锁定固定版本及显式评价时刻 |
| 权益额度 | CREDIT 定义条件更新、订单预留与 Outbox 发放 | 统一执行关联；不复制余额或重试系统 |
| 幂等 | 报价单次消费、订单命令键、权益来源键、Inbox | 营销参与 `(tenant,order,campaign)` 唯一键与结果投影幂等 |
| 可解释性 | 报价 Trace、活动/人群/权益固定引用 | 营销执行查询可同时看到决定、版本、权益终态与失败引用 |
| 运营与恢复 | 审批、暂停、事件隔离/恢复、命令审计 | 将失败执行与现有运行时恢复对象相连；不建第二套恢复入口 |

**切片边界：** 订单活动是同步资格/优惠决定，`JourneyService` 是带等待与分支的长期流程。优惠券、积分和外部现金利益各有独立权威与补偿语义；首个闭环只承诺单个内部 CREDIT，不把其可靠性泛化为所有利益类型。
