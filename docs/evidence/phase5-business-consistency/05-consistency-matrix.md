# Phase 5 consistency matrix

The test names are executable MySQL integration tests. A real payment/refund callback and a third-party WMS are not installed, so tests exercise the shared terminalization or local fulfillment boundary rather than claiming external adapter certification.

| Flow | Invariant | Concurrency Risk | Protection | Failure Recovery | Test Evidence |
|---|---|---|---|---|---|
| Order payment | one trusted provider fact and one order settlement | concurrent rechecks or redelivery | payment row/version guard, unique provider transaction, Outbox and Inbox | reobserve stable payment ID; retry pending event | `concurrentPaymentRechecksCommitOnePaidFactAndOneOrderEffect`; `paidFactWinsCancellationAndDuplicateDeliveryDoesNotDoubleConfirm` |
| Order expiry | paid order never expires; unresolved attempt retains reservations | stale candidate and payment/expiry race | due-state filter, locked state recheck, `CLOSING`, versioned transition | channel query resolves `CLOSING`; retry pending event | `staleExpiryCannotCancelAnAlreadyPaidOrder`; `twoLiveAppInstancesConvergeWhenExpiryRacesWithPaidRecheck`; `paidProviderFactConvergesAfterExpiryStartsClosing` |
| Fulfillment | one fulfillment obligation and legal shipment transition | event retry or concurrent ship/aftersale | `(tenant, order)` key, status/version guard, aftersale hold | retry failed event/command; no external WMS certification | `duplicateConcurrentShipmentCommandsCreateOneShipmentTransition`; `shipmentAndAftersaleRaceKeepsOneConsistentFulfillmentState` |
| Benefit | one source grant and bounded entitlement quota | duplicate grant or last quota unit | unique source, conditional quota update, guarded grant state and Inbox | retry requested grant; consumed benefit creates compensation debt | `entitlementIsReservedThenGrantedOnceAfterTrustedPayment`; `lastEntitlementQuotaLetsOnlyOneConcurrentOrderReserve`; `consumedEntitlementRefundCreatesExplicitCompensationDebt` |
| Points | one ledger effect per business source | duplicate event, refund or spend | unique source/refund/order keys and account/lot transaction | retry event; refund follows original allocation | `MemberPointsTest#netCashSourcesHandleEarlyRefundDuplicatesAndOriginalPolicy`; `PointsCheckoutTest#partialReturnsConserveCashAndIntegerPoints` |
| Coupon | quota and lifecycle remain valid | last issue, use/revoke/expiry race | definition row lock, conditional quota/status update, source key | failed transaction releases quota; full-return policy replays through Inbox | `couponQuotaIsSafeAcrossDifferentMembers`; `CouponDeliveryTest#couponReservationAndRevocationRaceHasOneWinner`; `partialRefundKeepsCouponUsedFullRefundReturnsAndOldEventCannotReleaseNewHold` |
| Refund | cumulative refund reservation does not exceed paid amount; one case refund | simultaneous requests/rechecks | conditional `refund_reserved` cap, unique case/provider transaction, row/version guard | keep `UNKNOWN` and capacity reservation; query same refund ID | `concurrentRefundReservationsCannotExceedReceivedAmount`; `duplicateConcurrentRefundRequestsReserveThePaymentOnlyOnce`; `concurrentRefundRechecksEmitOneSuccessAndCompleteOneCase` |
| After-sales | one active case and valid fulfillment relation | concurrent requests or shipment | fulfillment lock/hold, case version and active-case guard | conflicting request gets 409; unknown refund remains `REFUNDING` | `simultaneousAftersaleApplicationsLeaveOneActiveCase`; `shipmentAndAftersaleRaceKeepsOneConsistentFulfillmentState`; `refundEvidenceMismatchKeepsCaseOpenAndDoesNotRestoreInventoryTwice` |

The full transaction/dual-write inventory is in `04-transaction-matrix.md`; the scenario ledger in `14-concurrency-tests.md` identifies non-applicable provider-callback cases explicitly.
